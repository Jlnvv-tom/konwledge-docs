## 6.1 情境领导力（Situational Leadership）：因人而异的四风格切换

情境领导力由保罗·赫塞（Paul Hersey）和肯·布兰查德（Ken Blanchard）提出。核心原理：没有最好的领导风格，只有最适合当前情境的风格。

> 优秀的管理者不是固定一种风格，而是像变色龙一样根据下属的成熟度调整风格。

**情境领导的四风格矩阵：**

| 风格 | 英文 | 指导行为 | 支持行为 | 适用对象 | 典型对话 |
|------|------|---------|---------|---------|---------|
| 指示型 | Directing (S1) | 高 | 低 | 新手/低能力低意愿 | "按这个步骤做，有问题随时问" |
| 教练型 | Coaching (S2) | 高 | 高 | 有一定能力但需引导 | "你先试，我来看，一起复盘" |
| 支持型 | Supporting (S3) | 低 | 高 | 能力够但信心不足 | "你觉得怎么做？需要我什么支持？" |
| 授权型 | Delegating (S4) | 低 | 低 | 高能力高意愿 | "这个交给你了，定期同步" |

**下属成熟度四阶段与匹配风格：**

| 阶段 | 英文 | 能力 | 意愿 | 匹配风格 | 发展方向 |
|------|------|------|------|---------|---------|
| M1 | Enthusiastic Beginner | 低 | 高 | S1 指示型 | 快速积累技能 |
| M2 | Disillusioned Learner | 中低 | 低 | S2 教练型 | 重建信心+提升技能 |
| M3 | Capable but Cautious | 中高 | 波动 | S3 支持型 | 建立自主决策信心 |
| M4 | Self-Reliant Achiever | 高 | 高 | S4 授权型 | 挑战更大目标 |

**风格错配的后果：**

| 错配方式 | 下属感受 | 后果 | 修正 |
|---------|---------|------|------|
| S4管新手 | "被放弃了" | 出错率高、成长慢 | 降级到S1/S2 |
| S1管老手 | "不信任我" | 挫败感、考虑离职 | 升级到S3/S4 |
| S2管自驱者 | "管太多" | 觉得被微观管理 | 升级到S4 |
| S3管新手 | "没方向" | 迷茫、效率低 | 降级到S1 |

**情境领导风格切换的代码模型：**

```python
def select_leadership_style(member):
    """根据下属成熟度选择领导风格"""
    competence = member['competence']  # 1-5
    commitment = member['commitment']  # 1-5
    
    if competence <= 2 and commitment >= 3:
        return 'S1-指示型', '具体步骤指导，密切跟进'
    elif competence <= 3 and commitment <= 2:
        return 'S2-教练型', '指导+鼓励，一起复盘'
    elif competence >= 3 and commitment == 3:
        return 'S3-支持型', '少指导多支持，鼓励自主'
    elif competence >= 4 and commitment >= 4:
        return 'S4-授权型', '充分授权，定期同步'
    else:
        return 'S2-教练型', '默认教练型，观察调整'

# 团队风格分配
team = [
    {'name': '小张', 'competence': 1, 'commitment': 5},  # 新人热情高
    {'name': '老李', 'competence': 5, 'commitment': 4},  # 老手能干
    {'name': '小王', 'competence': 3, 'commitment': 2},  # 遇到瓶颈
]
for m in team:
    style, action = select_leadership_style(m)
    print(f"{m['name']}: {style} → {action}")
```

实践建议：列出你的团队成员，标注每个人的成熟度阶段（M1-M4），检查你当前的管理风格是否匹配。不匹配的，下周开始调整。

## 6.2 目标管理 OKR：从战略到执行的对齐

OKR（Objectives and Key Results）由安迪·格鲁夫（Andy Grove）在英特尔发展，约翰·杜尔（John Doerr）推广到谷歌。它的核心：用目标（O）指引方向，用关键结果（KR）量化进展。

> KPI关注"你做了什么"，OKR关注"你做成了什么"。前者考核动作，后者考核结果。

**OKR vs KPI 对比：**

| 维度 | OKR | KPI |
|------|-----|-----|
| 全称 | Objectives and Key Results | Key Performance Indicators |
| 目标性质 | 挑战性（70%完成即好） | 达标性（100%才算完成） |
| 透明度 | 全公司可见 | 通常仅上下级可见 |
| 调整频率 | 每季度 | 每年/每半年 |
| 与薪酬关系 | 弱关联或不关联 | 强关联 |
| 目的 | 对齐方向+激发挑战 | 考核绩效 |
| 失败容忍 | 鼓励挑战（60-70%完成是好的） | 不容忍未达标 |

**好的OKR vs 坏的OKR：**

| 维度 | 好的OKR | 坏的OKR |
|------|--------|--------|
| 目标(O) | 鼓舞人心、有挑战 | "维持现状" |
| 关键结果(KR) | 可量化、有数字 | "提升用户体验" |
| 数量 | 每季度3-5个O，每个O 3-4个KR | 20个目标 |
| 对齐 | 上下级OKR可见且对齐 | 各写各的 |
| 难度 | 70%完成率即算成功 | 100%才算达标 |

**OKR 评分机制表：**

| 完成度 | 评分 | 评价 | 调整建议 |
|--------|------|------|---------|
| <40% | 0.3 | 目标过大或执行不力 | 下调难度或增加资源 |
| 40-60% | 0.5 | 有进展但不够 | 检查执行障碍 |
| 60-70% | 0.7 | 理想状态 | 保持节奏 |
| 70-100% | 0.8-1.0 | 优秀 | 考虑下季加码 |
| 100% | 1.0 | 可能目标太低 | 下季提高难度 |

**OKR 评分计算的代码示例：**

```python
def okr_review(objectives):
    """OKR 季度评分"""
    for obj in objectives:
        kr_scores = []
        for kr in obj['key_results']:
            progress = kr['actual'] / kr['target']
            # OKR评分: 超过1.0封顶为1.0
            score = min(progress, 1.0)
            kr['score'] = round(score, 2)
            kr_scores.append(score)
        
        # O的分数 = KR平均分
        obj['score'] = round(sum(kr_scores) / len(kr_scores), 2)
        
        # 评价
        if obj['score'] >= 0.7:
            obj['verdict'] = '良好，目标设定合理'
        elif obj['score'] >= 0.4:
            obj['verdict'] = '一般，需检查执行'
        else:
            obj['verdict'] = '偏低，目标过大或执行不力'
    return objectives

# 示例
q1_okrs = [{
    'objective': '提升用户留存率',
    'key_results': [
        {'name': '次月留存率', 'target': 45, 'actual': 42},
        {'name': '召回成功率', 'target': 20, 'actual': 18},
        {'name': 'NPS分数', 'target': 50, 'actual': 55},  # 超额
    ]
}]
result = okr_review(q1_okrs)
# KR分数: 0.93, 0.90, 1.0 → O分数: 0.94
```

实践建议：每季度初设OKR时，问自己一个问题："如果只完成70%，这个结果是否仍然有价值？"如果否，说明目标不够挑战；如果是，说明目标合理。

## 6.3 赋能而非微观管理：管方向不管动作

微观管理（Micromanagement）是团队效率的隐形杀手。研究表明，被微观管理的员工，工作满意度降低40%，创造力降低35%，离职意愿增加50%。

**微观管理 vs 赋能管理对比：**

| 维度 | 微观管理 | 赋能管理 |
|------|---------|---------|
| 关注点 | 过程和动作 | 结果和方向 |
| 信任度 | 低 | 高 |
| 自主权 | 几乎没有 | 在边界内自由决策 |
| 反馈频率 | 每天多次 | 按里程碑 |
| 团队状态 | 等指令才动 | 主动推进 |
| 管理者状态 | 忙于跟细节 | 聚焦战略和障碍 |

**赋能的四个层次：**

| 层次 | 英文 | 决策权 | 管理行为 | 信任度 |
|------|------|--------|---------|--------|
| L1 | Tell | 管理者决定一切 | 指示+监督 | 最低 |
| L2 | Sell | 管理者决定，解释原因 | 说明+说服 | 低 |
| L3 | Consult | 下属建议，管理者决策 | 征求+采纳 | 中 |
| L4 | Agree | 共同决策 | 讨论+共识 | 高 |
| L5 | Delegate | 下属决策 | 授权+支持 | 最高 |

> 赋能不是放权不管，而是给方向、给资源、给边界，然后让下属在边界内自主决策。

**赋能决策模型代码：**

```python
def empowerment_level(task, member):
    """根据任务和成员决定赋能层次"""
    risk = task['risk']  # 1-5
    reversibility = task['reversibility']  # 1-5
    member_maturity = member['competence'] + member['commitment']
    
    # 低风险+高可逆+成熟成员 → L5充分授权
    if risk <= 2 and reversibility >= 4 and member_maturity >= 8:
        return 'L5-Delegate', '充分授权，只在里程碑检查'
    # 高风险+低可逆 → L1/L2管理者决策
    elif risk >= 4 or reversibility <= 2:
        return 'L2-Sell', '管理者决策，但解释原因'
    # 中等风险 → L3/L4共同决策
    else:
        return 'L4-Agree', '共同讨论，达成共识后执行'
```

实践建议：统计一下你这周替下属做了多少本该他们自己做的决策。如果超过5个，你在微观管理。下周开始，每次想插手时问自己："这个决策的后果我能承受吗？"如果能，让它去。

## 6.4 人才梯队建设与差异化激励

人才梯队（Talent Pipeline）是确保团队持续有人才可用。差异化激励（Differentiated Incentive）是确保好人才愿意留下。

**人才九宫格评估模型：**

| 绩效\潜力 | 低潜力 | 中潜力 | 高潜力 |
|----------|--------|--------|--------|
| 高绩效 | 专业骨干 | 核心骨干 | 超级明星 |
| 中绩效 | 稳定贡献者 | 关键贡献者 | 高潜人才 |
| 低绩效 | 观察期 | 待发展 | 问题员工 |

**九宫格的管理策略矩阵：**

| 格位 | 类型 | 人才策略 | 激励策略 | 发展投入 |
|------|------|---------|---------|---------|
| 高绩效+高潜力 | 超级明星 | 重点保留+加速发展 | 最高激励+股权 | 导师+轮岗+培训 |
| 高绩效+中潜力 | 核心骨干 | 保留+深耕 | 高于平均激励 | 专业深化 |
| 高绩效+低潜力 | 专业骨干 | 保留现状 | 稳定激励 | 维持现有 |
| 中绩效+高潜力 | 高潜人才 | 加速发展 | 中等激励+成长机会 | 培训+挑战任务 |
| 中绩效+中潜力 | 关键贡献者 | 稳定发展 | 平均激励 | 按需培训 |
| 中绩效+低潜力 | 稳定贡献者 | 维持 | 平均激励 | 最少 |
| 低绩效+高潜力 | 问题员工 | 诊断原因 | 暂缓激励 | 找原因再决定 |
| 低绩效+中潜力 | 待发展 | PIP(绩效改进) | 暂缓激励 | 针对性辅导 |
| 低绩效+低潜力 | 观察期 | 转岗或退出 | 无 | 不投入 |

**差异化激励的原则：**

| 原则 | 说明 | 反面案例 |
|------|------|---------|
| 区分度 | 优秀和普通应有明显差距 | 平均主义，大家拿一样 |
| 及时性 | 表现好立即奖励 | 年底才算总账 |
| 多元化 | 钱不是唯一激励 | 所有激励都是奖金 |
| 透明度 | 规则公开透明 | 暗箱操作 |
| 可持续 | 激励不透支未来 | 承诺过多无法兑现 |

**人才九宫格定位的代码：**

```python
def talent_grid(performance, potential):
    """
    performance: 1-5 (绩效)
    potential: 1-5 (潜力)
    返回九宫格类型和管理策略
    """
    p = '高' if performance >= 4 else ('中' if performance >= 3 else '低')
    pot = '高' if potential >= 4 else ('中' if potential >= 3 else '低')
    
    grid = {
        ('高', '高'): ('超级明星', '加速发展+最高激励+股权'),
        ('高', '中'): ('核心骨干', '保留+深耕+高于平均激励'),
        ('高', '低'): ('专业骨干', '保留现状+稳定激励'),
        ('中', '高'): ('高潜人才', '加速发展+挑战任务'),
        ('中', '中'): ('关键贡献者', '稳定发展+平均激励'),
        ('中', '低'): ('稳定贡献者', '维持+平均激励'),
        ('低', '高'): ('问题员工', '诊断原因+暂缓激励'),
        ('低', '中'): ('待发展', 'PIP+针对性辅导'),
        ('低', '低'): ('观察期', '转岗或退出'),
    }
    return grid.get((p, pot), ('未知', '需评估'))
```

> 对待超级明星和问题员工的态度，决定了团队的公平感。如果你对低绩效者手软，就是对高绩效者的惩罚。

## 6.5 心理安全感建设：让团队敢于说真话

心理安全感（Psychological Safety）由哈佛教授艾米·埃德蒙森（Amy Edmondson）定义：团队成员相信，即使展现自我、提出想法、承认错误，也不会受到惩罚或羞辱。

> 谷歌Project Aristotle研究180个团队后发现，预测团队效能的第一因子不是成员能力，而是心理安全感。

**心理安全感的四个阶段：**

| 阶段 | 英文 | 核心问题 | 管理者行为 | 团队表现 |
|------|------|---------|-----------|---------|
| 包容安全感 | Inclusion Safety | 我被接纳吗？ | 主动邀请、尊重差异 | 新人敢于参与 |
| 学习安全感 | Learner Safety | 我可以犯错吗？ | 将错误视为学习机会 | 主动提问、承认不会 |
| 贡献安全感 | Contributor Safety | 我可以挑战现状吗？ | 认可不同意见 | 提出新想法 |
| 挑战安全感 | Challenger Safety | 我可以挑战权威吗？ | 欢迎对上级提出质疑 | 指出上级的问题 |

**心理安全感评估表（1-5分）：**

| 评估项 | 低安全感表现 | 高安全感表现 | 你的团队分数 |
|--------|------------|------------|------------|
| 敢于提反对意见 | 开会沉默，会后抱怨 | 当面提出不同看法 | ___/5 |
| 敢于承认错误 | 隐藏错误或甩锅 | 主动说"这个我没做好" | ___/5 |
| 敢于提问 | 怕被笑话不提问 | 不懂就问，不分层级 | ___/5 |
| 敢于创新 | 只做分内事 | 主动提出改进方案 | ___/5 |
| 敢于挑战上级 | 一律附和上级 | 敢说"我觉得你这个方向不对" | ___/5 |

**心理安全感建设行为清单：**

| 行为 | 频率 | 效果 | 示例 |
|------|------|------|------|
| 公开承认自己的错误 | 每周至少1次 | 建模效应 | "上周我的判断错了，纠正一下" |
| 邀请反对意见 | 每次会议 | 打破附和 | "谁不同意？说出来" |
| 对报错表示感谢 | 每次报错时 | 降低报错成本 | "感谢你及时告诉我" |
| 不追究"谁的责任" | 问题发生时 | 聚焦解决 | "先解决问题，原因后面复盘" |
| 表彰说真话的人 | 每周 | 强化正向行为 | "小王这个问题提得好" |

**心理安全感评分追踪的代码模型：**

```python
def psych_safety_score(survey_results):
    """团队心理安全感评分"""
    dimensions = {
        'inclusion': survey_results['inclusion'],
        'learner': survey_results['learner'],
        'contributor': survey_results['contributor'],
        'challenger': survey_results['challenger'],
    }
    avg = sum(dimensions.values()) / len(dimensions)
    
    if avg >= 4.0:
        return f'{avg:.1f}/5 - 高安全感，团队健康'
    elif avg >= 3.0:
        return f'{avg:.1f}/5 - 中等，需在弱项加强'
    else:
        weak = min(dimensions, key=dimensions.get)
        return f'{avg:.1f}/5 - 偏低，最弱项: {weak}，急需改善'
```

实践建议：每季度做一次匿名心理安全感调查。如果"敢于挑战上级"这一项低于3分，问题出在你身上，不在团队身上。

## 6.6 一对一会议（1-on-1）：管理者的基本功

1-on-1是管理者和下属之间最高频、最重要的沟通机制。它不是进度汇报会，而是下属的成长支持会。

**1-on-1 vs 进度汇报的区别：**

| 维度 | 1-on-1 | 进度汇报 |
|------|--------|---------|
| 主导者 | 下属 | 管理者 |
| 主要内容 | 成长、障碍、反馈 | 进度、数据、风险 |
| 频率 | 每周或每两周 | 按需 |
| 氛围 | 开放、安全 | 正式、结构化 |
| 产出 | 行动项+成长计划 | 进度看板更新 |
| 时长 | 30-45分钟 | 15-30分钟 |

**1-on-1 标准议程模板：**

| 时间段 | 内容 | 主导者 | 目的 |
|--------|------|--------|------|
| 0-5分钟 | 破冰+情绪check-in | 双方 | 建立连接 |
| 5-15分钟 | 下属想聊的事 | 下属 | 倾听和支持 |
| 15-25分钟 | 管理者想聊的事 | 管理者 | 反馈和对齐 |
| 25-35分钟 | 成长和发展 | 双方 | 长期发展 |
| 35-40分钟 | 行动项确认 | 双方 | 明确next steps |

**1-on-1 好问题清单：**

| 类别 | 问题 | 目的 |
|------|------|------|
| 情绪 | "这周状态怎么样？1-10打几分？" | 情绪监测 |
| 障碍 | "有什么阻碍你把工作做好？" | 排除障碍 |
| 反馈 | "你希望我多做/少做什么？" | 向下反馈 |
| 成长 | "最近学到什么新东西？" | 发展关注 |
| 挑战 | "什么工作让你有成就感？" | 动机识别 |
| 团队 | "团队有什么你觉得需要改的？" | 组织感知 |

**1-on-1 记录追踪的代码模板：**

```python
from datetime import datetime

class OneOnOne:
    def __init__(self, member_name):
        self.member = member_name
        self.history = []
    
    def add_session(self, date, mood_score, topics, 
                    action_items, feedback_given, 
                    feedback_received):
        """记录一次1-on-1"""
        self.history.append({
            'date': date,
            'mood': mood_score,  # 1-10
            'topics': topics,
            'actions': action_items,
            'given': feedback_given,
            'received': feedback_received,
        })
    
    def trend(self):
        """分析情绪趋势"""
        moods = [h['mood'] for h in self.history]
        if len(moods) < 2:
            return "数据不足"
        trend = moods[-1] - moods[0]
        if trend > 1:
            return f"情绪上升(+{trend})，状态改善"
        elif trend < -1:
            return f"情绪下降({trend})，需要关注"
        else:
            return "情绪稳定"

# 管理建议: 连续3次mood<6，需要深入对话
```

> 1-on-1是你对团队每个成员最重要的投资。每周30分钟，换来的是信任、对齐和早期预警。

## 6.7 服务型领导（Servant Leadership）与文化塑造

服务型领导由罗伯特·格林利夫（Robert Greenleaf）提出。核心理念：管理者的首要角色是服务团队，而非指挥团队。

**服务型领导 vs 传统领导的对比：**

| 维度 | 传统领导 | 服务型领导 |
|------|---------|-----------|
| 核心问题 | "下属能为我做什么？" | "我能为下属做什么？" |
| 权力来源 | 职位赋予 | 信任积累 |
| 决策方式 | 自上而下 | 参与式 |
| 成功标志 | 任务完成 | 团队成长 |
| 资源流向 | 向上集中 | 向下赋能 |
| 管理者感受 | 被需要 | 被信任 |

**团队文化塑造的三个杠杆：**

| 杠杆 | 英文 | 作用 | 实施方法 |
|------|------|------|---------|
| 制度 | Systems | 定义规则 | 流程、考核、晋升标准 |
| 行为 | Behaviors | 建立标杆 | 管理者以身作则 |
| 语言 | Language | 塑造思维 | 特定词汇、仪式、故事 |

> 文化不是墙上贴的标语，而是当管理者不在场时团队的行为方式。塑造文化最有效的工具不是制度，而是你每天的行为。

实践建议：问自己一个问题——"如果我不在团队一周，团队会做出什么决策？"如果答案是"可能会乱"，说明你的文化是依赖个人的；如果答案是"和我在一起时差不多"，说明文化已经建起来了。
