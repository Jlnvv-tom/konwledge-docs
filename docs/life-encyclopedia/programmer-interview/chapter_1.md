# 程序员面试100问·第1篇：求职准备——面试从投简历之前就开始了

你以为面试是从投出简历那一刻开始的？其实从你决定跳槽的那天起，面试就已经开始了。你过去三年的项目积累、你平时有没有写技术博客、你刷过多少道题、你对自己职业的规划是否清晰，全都在你开口之前就被"预审"了一遍。

我是怕浪猫，一个在互联网行业做了八年开发、面过两百多场技术面试的"老油条"。这些年我见过太多人：简历写得很漂亮，一进笔试就露馅；技术很强，却因为投错了渠道连面试机会都没有。这个系列，我把程序员求职从笔试到入职的完整链路拆成十篇，一篇一个环节，帮你把每一关都走稳。今天是第一篇，讲面试真正开始的地方——求职准备。

## 1.1 求职战略三分法：应届生、社招、转行程序员

很多人一上来就打开招聘软件海投，这是最大的误区。不同身份的人，面试官对你的期待完全不同，你的准备重点也完全不同。先搞清楚自己是哪一类，再谈后面的所有动作。

应届生的核心问题是"没有经验"，面试官考察的是潜力：基础扎不扎实、学习能力强不强、有没有做过像样的项目。所以应届生的弹药是：扎实的计算机基础、两三个能讲透的项目、足够的刷题量。对应届生来说，秋招（每年九月到十一月）和春招（次年三月到五月）是两大窗口期，秋招岗位最多、质量最高，春招主要是补录和考研落榜生的机会，还有不少公司设有提前批，七月八月就开始面试。应届生拼的是"下限"，只要基础过关、态度诚恳、项目能自圆其说，机会就很多。

社招的核心问题是"经验是否匹配"。面试官默认你是有经验的工程师，考察的是：项目深度、系统设计能力、踩坑经验、以及你和目标岗位的匹配度。社招拼的是"上限"，你需要的是把过去做过的项目讲到面试官挑不出毛病，并且让对方相信你来了就能上手干活。社招看岗位描述（JD，Job Description）是一门学问：JD里的每一项要求都要对照自己的经历，能对上的准备一个故事，对不上的评估差距有多大。

转行程序员最尴尬：经验不足，又不被当应届生对待。转行者的核心策略是"用作品说话"——用开源项目、技术博客、个人网站来证明你的能力，让面试官相信你不是只背了八股文。我认识一个从传统行业转行的朋友，零相关经验，靠一个维护了两年的开源项目拿到了中厂的offer，面试官原话是"这个项目的代码质量比很多在职的强"。作品就是转行者的简历。

| 身份 | 面试官考察 | 你的弹药 | 主要战场 |
|------|-----------|----------|----------|
| 应届生 | 潜力、基础、学习能力 | 基础+项目+刷题量 | 秋招/春招/提前批 |
| 社招 | 经验匹配、项目深度 | 项目故事+系统设计 | 全年滚动 |
| 转行者 | 作品、学习能力、热情 | 开源项目+博客 | 全年滚动 |

> 应届生卖潜力，社招卖经验，转行者卖作品——面试官买的从来不是你的简历，而是你能解决的问题。

你属于哪一类？先给自己定位，再谈投递，否则投再多简历都是浪费。你有没有想过，你上一份工作最值得被拿出来讲的项目是哪个？如果一时答不上来，说明你连"弹药"都还没准备好。

## 1.2 目标公司梯队与求职时间线

定位好身份之后，第二步是确定目标公司梯队。我把公司分成四档：大厂、中厂、小厂、外包。这四档的面试难度、薪资水平、工作强度、职业履历价值完全不同，没有绝对的好坏，只有适不适合你当前的阶段。

大厂指一线互联网公司，面试最规范也最难：简历筛选、笔试、三到四轮技术面、HR面环环相扣，考察全面。大厂的好处是技术体系成熟、晋升通道清晰、履历背书强，适合追求技术成长和长期职业发展的人。代价是流程长，从投递到拿offer动辄一个多月，而且对算法和基础的要求很高。

中厂指二三线互联网公司和独角兽企业，面试相对灵活，可能跳过笔试或减少轮次，更看重项目匹配度和解决问题的能力。中厂的薪资往往不比大厂差，很多还有期权（Option，未来以约定价格购买公司股票的权利），氛围和成长空间也不错，是性价比很高的选择。

小厂指创业公司和传统企业的数字化部门，面试最快，通常一两轮就定，看重"来了就能干活"。小厂适合想快速拿offer、想要更多主导权和技术广度的人，但平台稳定性差一些，简历背书弱一些。

外包（人力外包）门槛最低，你以供应商身份驻场在甲方工作，合同签在第三方公司。外包的薪资天花板低、转正机会少、履历含金量低，一般不建议作为首选，但如果你目前处于空窗期需要过渡，可以作为权宜之计，同时要保持继续面试的状态。

求职时间线也有讲究。传统认知里的"金三银四"（三、四月）和"金九银十"（九、十月）确实还是招聘旺季，背后的原理是：年初年终奖发完，很多人选择拿完钱再走；公司年度预算和HC（Headcount，人员编制名额）批复下来，放出的岗位最多。但旺季意味着竞争也最激烈。现在很多公司全年都在滚动招聘，尤其是急招岗位，反而在淡季竞争更小。

我的建议是：准备期至少提前三到六个月启动。前三个月用来补齐短板（刷题、复盘项目、整理简历素材），后三个月进入投递和面试状态。不要等到想离职了才开始准备，那是最被动的状态。

> 旺季是公司的旺季，淡季才是你的机会——人少的时候，你的简历被看到的概率反而更大。

## 1.3 投递渠道全解：内推、猎头、官网、招聘软件

投递渠道决定了你的简历被谁看到、以什么优先级被看到。常见渠道按效率排序：内推、猎头、官网直投、招聘软件海投。这不是我拍脑袋排的，而是基于简历的"触达路径"长短。

内推是效率最高的渠道，原理是信任前置：内推简历会直接进入业务部门面试官的视野，绕过HR的初筛，而且面试官对被推荐人天然多一分信任，因为推荐人用自己的信誉做了背书。怎么找内推？脉脉、领英（LinkedIn，全球职场社交平台）、技术社区、前同事，都是靠谱来源。找内推时记得给推荐人发一份完整简历和一句简短的自我介绍，别让人家帮你传话都传不清楚。

猎头适合有几年经验、目标明确的中高级程序员。猎头手里往往有未公开的岗位，还能帮你谈薪资、同步面试反馈。但要注意辨别猎头质量：专业猎头会先了解你的诉求再推荐岗位，不专业的猎头只会群发职位、套你的简历。判断标准很简单，看他有没有认真读过你的简历。

官网直投适合目标明确的大厂。大厂的招聘官网信息最准确、流程最规范，缺点是简历进入统一人才库后可能被"泡池子"——简历进了库，但迟迟没人捞。应对办法是投递后主动跟进，或者换个渠道再投一次。

招聘软件（BOSS直聘、拉勾等）适合广撒网，但效率最低。因为投递量大，HR平均看一份简历不到三十秒，你的简历必须在前半屏就抓住重点。打招呼话术也有讲究，别用系统默认的"您好，我对贵公司职位很感兴趣"，改成"您好，我做过三年Java后端，主导过日活百万的订单系统，和贵司岗位要求匹配，简历已附上"，被回复的概率会高很多。

| 渠道 | 简历触达路径 | 效率 | 适合人群 |
|------|-------------|------|----------|
| 内推 | 直达业务面试官 | 高 | 所有人 |
| 猎头 | 猎头筛选后推荐 | 中高 | 中高级社招 |
| 官网 | 进统一人才库 | 中 | 目标明确的大厂 |
| 招聘软件 | HR批量筛选 | 低 | 广撒网、应届生 |

> 内推拼关系，猎头拼经验，官网拼匹配，海投拼运气——投递渠道的优先级，就是你求职效率的优先级。

## 1.4 简历制作：STAR法则量化项目

简历是你唯一的"产品说明书"，而HR和面试官看简历的方式完全不同。HR看的是关键词和硬性条件：学历、年限、技术栈、公司背景，平均三十秒扫完一份，这一关叫"简历筛选"。业务面试官看的是项目深度：你做了什么、怎么做的、结果如何，他们会在面试里针对简历逐条追问。所以简历上的每一个字，都必须经得起追问。

项目经历是简历的灵魂，一定要用STAR法则来写。STAR是四个英文单词的缩写：Situation（情境）、Task（任务）、Action（行动）、Result（结果）。核心原理是：面试官不关心你"负责过什么"，关心的是你在具体情境下如何行动、产生了什么可量化的结果。结构化描述能让面试官在最短时间内判断你的能力层级。

举个例子，"负责订单系统开发"是无效描述，因为它没有情境、没有行动、没有结果。改成这样：Situation是"订单系统支撑日均10万单，大促期间经常超时"；Task是"优化下单链路性能"；Action是"引入Redis（Remote Dictionary Server，远程字典服务）缓存热点数据、将下单流程改为异步化"；Result是"接口平均耗时从800毫秒降到120毫秒，机器成本降低40%"。后者才是面试官想看到的东西。

再强调一遍数字的威力：有量化结果的项目描述，说服力是空洞描述的五倍以上。数字就是证据，证据越多，面试官越难质疑你的项目真实性。

简历的常见红线也要避开。第一，技能栈不要写"精通"——除非你真能达到源码级理解，否则面试官追问两轮就会露馅，"熟悉"和"掌握"是更安全的表述，配合具体的应用场景描述更有说服力。第二，工作经历不要造假，背景调查（Background Check，背调）环节会通过社保记录、前同事核实你的履历，造假被发现直接凉凉，还可能上行业黑名单。第三，空窗期不要撒谎，如实说明并讲清楚这段时间做了什么（学习、开源项目、个人作品），比遮遮掩掩好得多。第四，频繁跳槽要用合理的叙事解释，比如"前两年在探索方向，近两年已经稳定深耕某个领域"，让面试官相信你现在是稳定状态。

写简历时问自己一个问题：如果我拿着这份简历面自己，能问出几个问题？问不出来，说明写得不够具体。简历写完后放两天再回看，你会发现很多自己当时觉得理所当然、别人根本看不懂的表述。

> 简历不是自我表扬信，而是证据链——每一个结论，都要有可被追问的细节支撑。

## 1.5 笔试刷题战略：LeetCode高频题规划

笔试是求职的第一道硬门槛，也是准备周期最长、最需要提前规划的环节。很多人的误区是"刷题就是刷量"，其实刷题的核心是"按考点刷、按套路刷、按平台刷"。

先定目标。以国内大厂为参考，笔试和面试的算法题基本集中在这些考点：数组与字符串、链表、树、哈希表、双指针、滑动窗口、二分查找、动态规划（DP，Dynamic Programming）、深度优先搜索（DFS，Depth First Search）、广度优先搜索（BFS，Breadth First Search）。LeetCode（力扣，全球最大的算法刷题平台）上的热门题（Hot 100）和剑指Offer系列，覆盖了绝大多数考点，建议优先刷完这两块，再根据目标公司的面经查漏补缺。

再定方法。每道题要过三遍：第一遍自己思考三十分钟，想不出来就看题解，但看完一定要自己重写一遍；第二遍隔天独立写出来，检验是否真的理解；第三遍隔一周重做，检验长期记忆。光看不写等于没刷，光写不复盘等于白刷。刷题过程中要建立"套路库"：双指针解决有序数组问题、滑动窗口解决子串问题、二分查找解决单调性问题，这些套路在笔试里就是你的肌肉记忆。

刷题平台也有规则要懂。牛客网、赛码网等国内笔试平台用的是ACM模式（以美国计算机协会命名，ACM，Association for Computing Machinery，这种模式要求自己处理输入输出），而LeetCode用的是核心代码模式（只需要实现函数，输入输出由平台处理）。笔试前一定要去目标平台做几道模拟题，熟悉输入输出格式，否则考试时光调输入输出就能浪费半小时。举个最简单的例子，ACM模式读入两个整数并求和：

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int a = sc.nextInt();
        int b = sc.nextInt();
        System.out.println(a + b);
    }
}
```

这段代码的要点是：必须导入Scanner类、必须自己读入并输出，主类名通常是Main。很多人第一次用ACM模式，卡在"为什么我写了函数却没有输出"上，其实就是没搞懂模式差异。

还有一个很多人忽略的点：笔试环境。在线笔试通常要求开摄像头、全程监控，切屏超过一定次数会被系统警告甚至直接判作弊。系统检测切屏的原理是监听浏览器窗口失焦事件——当你的浏览器失去焦点，系统就会记录一次切屏。所以笔试前务必关闭所有无关软件、关掉消息弹窗、把手机放远，同时确认网络稳定、电脑能正常编译、IDE（Integrated Development Environment，集成开发环境）配置无误。因为环境问题挂掉笔试，是最冤的挂法。这部分我会在第二篇详细展开。

> 刷题刷的不是数量，是套路——同一类题做十道，不如一类题吃透三种变形。

笔试挂掉不可怕，可怕的是挂了之后不知道自己挂在哪。每次笔试后复盘：是审题不清、边界漏判、还是复杂度超限？把错误记下来，下次针对性补。复盘做得好，一次失败顶十次盲目刷题。

## 1.6 求职时间规划表：倒推你的准备节奏

求职准备最怕"感觉在准备，其实没进展"。把求职当成一个项目来管理，用倒推法排出时间表，每一步都有产出物，进度看得见。

假设你的目标是三个月后拿到offer，倒推时间线是这样的：第一个月做弹药准备——刷题（每天两到三题，一个月积累六十到九十题）、复盘项目（把两到三个重点项目用STAR结构写好讲稿）、整理简历（初稿加两轮修改）。第二个月进入火力侦察——投递第一批简历（十到二十家，覆盖目标梯队）、参加笔试、积累面试经验，同时根据反馈迭代简历和话术。第三个月进入决战阶段——加大投递量（每周十家以上）、集中面试、谈offer、做决策。

每周的节奏也要排：周一投递和跟进，周二到周四刷题和复盘，周五约面试，周末做周复盘。求职是持久战，节奏感比爆发力重要。每日时间分配参考：刷题两小时、投递和跟进一小时、项目复盘和八股一小时，有面试的日子再预留两到三小时。没有面试的日子，时间是够用的，关键是别让"没有面试"变成"没有安排"。

> 求职不是等来的，是排出来的——把目标拆成周计划、日计划，每一天都有产出，焦虑自然就少了。

## 1.7 求职准备FAQ：高频疑问快答

Q1：现在行情不好，要不要等一等再求职？
行情没有绝对的好与坏，只有相对的竞争强度。与其等行情，不如等自己准备好。你把弹药备齐了，行情再差也有你的位置；你什么都没准备，行情再好也轮不到你。

Q2：简历要不要写照片、年龄、籍贯？
不需要。简历的核心是能力和经历，无关的个人信息不仅占版面，还可能触发无意识的偏见。只保留招聘方真正需要的：联系方式、学历、经历、技能、项目。

Q3：项目经历太少怎么办？
项目经历不等于工作项目。课程设计、毕业设计、个人项目、开源贡献、比赛作品，都可以写。关键不是项目大小，而是你在里面做了什么、解决了什么问题、产出了什么结果。

Q4：要不要报培训班？
培训班的本质是花钱买节奏和资料，值不值取决于你的自制力。自制力强的人，免费资料加刷题平台完全够用；自制力弱的人，培训班提供一个外部约束。但别指望培训班包工作，那是不现实的。

Q5：刷题和项目哪个优先？
看你缺什么。笔试都过不了，先刷题；笔试能过但面试聊项目时讲不出东西，先补项目。普遍的建议是两条腿走路：刷题保持手感，项目复盘保持深度，每天各分配时间。

Q6：在职求职怎么请假面试？
利用年假、调休，或者约早晚的面试时间。别频繁请假，容易引起注意。更推荐的做法是约远程面试，很多公司技术面支持视频面试，灵活度高。

Q7：空窗期太长简历怎么写？
如实写，别造假。空窗期做了学习、开源、接单，就写出来，都是产出。面试被问到就讲清楚时间安排和产出，坦诚比遮掩更让人信任。

Q8：要不要海投？
可以海投，但要"精准海投"：根据你的定位筛选出匹配度高的岗位再投，而不是见岗就投。精准海投的目的是扩大触达面，不是降低简历质量。

> 准备的深度，决定求职的长度——把每个疑问提前想清楚，面试时你才能从容。
