# 程序员面试100问·第2篇：笔试实战——第一道大规模淘汰闸门

我参加过几十场在线笔试，前七场挂得毫无悬念。不是不会做，而是我根本不懂笔试的规则：不知道ACM模式要自己处理输入输出，不知道切屏会被记录，不知道有的题型分值占比极小、耗时却极高。直到我搞懂了笔试的"底层机制"，通过率才真正提上来。

我是怕浪猫，八年开发经验，面过两百多场技术面试。上一篇讲了求职准备，今天进入第一个实战环节：笔试。笔试是求职路上第一道大规模淘汰闸门，很多公司的笔试淘汰率超过百分之五十，也就是说，一半以上的人连面试官的面都见不到。这一篇，我把笔试的规则、机制、套路一次讲透。

## 2.1 在线笔试的完整流程与反作弊机制

先搞清楚在线笔试的完整流程，你才知道自己面对的是什么。以国内主流笔试平台为例，流程一般是：HR或系统发送笔试邀请邮件，邮件里有笔试链接、时间窗口和注意事项；到了约定时间，你打开链接，系统会先做环境检测（摄像头、麦克风、浏览器兼容性），然后进入答题页面；答题结束后系统自动交卷，成绩同步给招聘方。

整个流程中最容易翻车的是环境检测环节。系统会检测你是否开启了摄像头，有的还会要求第二机位（手机从侧后方拍摄）。如果摄像头检测不通过，你连答题页面都进不去，直接失去这次笔试机会。所以笔试前一定要提前半小时进入系统，把所有检测流程走一遍，不要等到开考了才发现摄像头权限没开。

再讲反作弊机制，这是很多人吃亏的地方。在线笔试的防作弊体系大致分三层：行为监控、内容比对、异常标记。

行为监控的原理是监听浏览器事件。当你切换标签页或最小化窗口时，浏览器会触发失焦事件（blur事件），系统记录一次"切屏"。切屏次数超过阈值（通常三到五次）会触发警告，严重的直接判作弊。还有一个细节：鼠标轨迹分析。系统会记录你的鼠标移动轨迹，如果轨迹异常（比如长时间不动后突然精准点击），会被标记为可疑。

内容比对的原理是代码查重。系统会用查重算法把你的代码和全网公开代码、其他考生的代码做相似度比对。相似度超过阈值（通常是百分之七十到八十）会被判定抄袭。查重算法常用的是哈希分段比对：把代码按固定长度切段，每段计算哈希值（Hash，把任意长度数据映射为固定长度值的函数），然后统计重合比例。所以抄网上的模板代码，在查重系统面前几乎是裸奔。

异常标记是最后一层：系统会综合你的切屏次数、答题速度、正确率分布等特征，给出一份"异常报告"给招聘方，由人工判断是否作废。所以即使系统没当场判你作弊，异常行为也可能在事后被翻出来。

> 笔试考的不只是你会不会，还有你懂不懂规则——规则都搞不清的人，公司凭什么相信你能搞定线上事故？

你有没有在笔试时切过屏？哪怕只是看个消息，都可能被记录。

## 2.2 题型分布与时间分配：得分优先级

国内笔试的题型大致分四类：单选题、多选题、编程题、问答题。不同类型的分值和耗时差异巨大，时间分配策略直接决定你的得分上限。

单选题通常考察基础概念：数据结构、操作系统、计算机网络、数据库、语言特性，每题分值低（一到两分）但速度快。多选题类似，但选错倒扣分的规则需要注意——很多平台多选漏选得部分分、错选倒扣分，不确定的选项宁可不选。

编程题是大头，通常两到四道，分值占比最高（一道可能占二三十分），是决定通过与否的关键。编程题又分两种：部分通过制（有多个测试用例，通过几个给几分）和全通过制（全部测试用例通过才给分）。绝大多数平台是部分通过制，这意味着"暴力解法过部分用例"也能拿分，绝对不能留空。

问答题较少见，主要出现在校招笔试里，考察系统设计或场景分析，分值中等。

时间分配的原则是"先易后难、先分高后分低"：开考后先用十分钟快速扫一遍全部题目，标记出会做的、半会不会的、完全不会的；然后优先做单选和多选（快速拿基础分），再做有思路的编程题，最后啃难题。编程题如果卡住超过二十分钟，果断放弃，把时间留给能拿分的题。

这里有个关键认知：笔试是"得分游戏"不是"解题游戏"。目标是总分过线，不是每道题都做对。一道编程题暴力解法能过百分之六十的用例，就比死磕最优解导致后面题目没时间做要划算得多。

> 笔试是得分游戏，不是解题游戏——你不需要每道题都做对，你需要总分过线。

一个实操技巧：先把所有编程题的"输入输出框架"写出来。这样即使某道题没做出来，只要框架正确、部分逻辑正确，也能拿到基础分。留空和写了一半，得分天差地别。

## 2.3 笔试挂掉的高频原因：审题、边界、复杂度

挂了七场笔试之后，我把所有失败原因做了归类，发现高频原因就三类：审题不清、边界漏判、复杂度超限。这三类问题各有各的解法。

审题不清是最冤的挂法。题目要求"返回所有不重复的组合"，你写成了"返回所有组合"；题目要求"原地修改"（in-place，直接在原数组上操作，不返回新数组），你新建了数组。这类错误在本地自测时往往测不出来，因为样例数据恰好没覆盖差异点。解法是：读题时圈出关键词（不重复、原地、升序、最小、最多），把题目要求转成自己的话复述一遍再动手。

边界漏判是第二高频原因。数组为空、只有一个元素、元素全相同、目标值不在范围内、整数溢出——这些边界情况是测试用例的重点，也是扣分重灾区。解法是：写代码时先想清楚边界条件再写主逻辑，写完代码后主动构造边界用例自测。一个习惯：写完代码先跑三个用例——空输入、最小输入、最大输入。

复杂度超限是第三高频原因，也是最容易被忽略的。题目数据范围是十的五次方，你写了个O(n²)（平方复杂度，n为数据规模，时间复杂度随数据规模平方增长）的算法，用例全对，但超时判负。解法是：动手前先估算复杂度——看数据范围，如果n是十的五次方，O(n²)基本必挂，必须想O(n)或O(n log n)的解法。

| 挂因 | 典型表现 | 根因 | 对策 |
|------|----------|------|------|
| 审题不清 | 输出格式不符 | 没圈关键词 | 复述题目再动手 |
| 边界漏判 | 空数组报错 | 没构造边界用例 | 主动测空/最小/最大 |
| 复杂度超限 | 用例对但超时 | 没估算数据范围 | 先估复杂度再写 |

> 挂笔试的三座大山：审题不清是粗心，边界漏判是习惯，复杂度超限是思维——前两个能改，第三个要练。

## 2.4 高频算法模板速记：套路库

笔试高频算法题集中在几大类，每一类都有固定的套路。掌握套路不是背题，而是理解每一类问题背后的核心原理，这样遇到变形题也能举一反三。

双指针是解决有序数组问题的利器。核心原理：一个指针从头部开始，一个指针从尾部开始，根据当前两个指针指向元素的和与目标值的大小关系，决定移动哪个指针，时间复杂度从O(n²)降到O(n)。典型场景：有序数组两数之和。

滑动窗口解决子串、子数组问题。核心原理：维护一个窗口（用两个指针表示左边界和右边界），右指针不断右移扩大窗口，当窗口内条件不满足时左指针右移缩小窗口。典型场景：无重复字符的最长子串。这个套路背后是"单调性"的利用——窗口扩大时条件的变化是单调的，所以可以线性推进。

二分查找解决单调性问题。核心原理：在一个有序序列中，每次取中间元素与目标比较，根据比较结果排除一半的搜索空间。关键易错点是边界条件：左闭右闭区间和左闭右开区间的写法不同，循环条件一个用left <= right，一个用left < right，搞混就会死循环或漏解。

深度优先搜索（DFS，Depth First Search）和广度优先搜索（BFS，Breadth First Search）解决遍历类问题。DFS的核心原理是沿着一条路径走到底再回溯，用递归或栈实现；BFS是逐层扩散，用队列实现。BFS适合求最短路径（因为逐层扩散天然保证首次到达就是最短），DFS适合枚举所有可能（全排列、组合）。这里给一个DFS的经典模板骨架：

```python
def dfs(path, choices):
    if 满足结束条件:
        记录结果
        return
    for choice in choices:
        if choice 不合法:
            continue
        path.append(choice)   # 做选择
        dfs(path, new_choices)  # 递归
        path.pop()            # 撤销选择（回溯）
```

这段代码的核心是三段式：做选择、递归、撤销选择。撤销选择（回溯）是DFS的灵魂——它保证了每条路径探索完能恢复现场，从而枚举所有可能性。

动态规划（DP，Dynamic Programming）是笔试压轴题的最爱。核心原理：把大问题分解成重叠子问题，用数组记录子问题的解，避免重复计算。识别DP题的关键特征：求最值、有状态转移关系、子问题重叠。经典入门题是爬楼梯：走到第n级台阶的方法数等于走到第n-1级和第n-2级的方法数之和，状态转移方程是dp[n] = dp[n-1] + dp[n-2]。

二分查找再给一个左闭右闭的标准写法，边界处理是它最容易出错的地方：

```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
```

这里有两个关键点：循环条件用left <= right（因为左闭右闭区间里left == right时区间还有一个元素）；mid用left + (right - left) / 2计算而不是(left + right) / 2，是为了防止left加right溢出整数范围。

> 套路不是背答案，是理解原理后的条件反射——看到"有序+查找"想到二分，看到"子串"想到滑动窗口。

刷题的时候不妨把每道题的"触发关键词"记下来：什么特征对应什么套路。积累够五十道，你就能建立自己的套路库。

## 2.5 大厂笔试风格差异与智力题应对

不同公司的笔试风格差异很大，了解目标公司的出题偏好，能让你准备得更精准。

字节跳动系的笔试以算法题为主，题目难度梯度明显：前一两道是基础题（链表、字符串处理），后面是中等偏难的数据结构和动态规划题。字节特别看重代码的完整性和边界处理，部分通过制的用例设计很细，审题不清基本必挂。

腾讯系的笔试编程题偏工程化，有时候会出现和业务场景结合的题目，比如设计一个缓存、处理一个数据流。腾讯的单选题考察面广，计算机网络和操作系统占比高。

阿里系的笔试风格偏"思维深度"，编程题少而精，但每道题都可能有多个考点叠加，比如"树+动态规划"组合。阿里也比较喜欢智力题和逻辑题，考察思维方式。

美团系的笔试性价比最高，题目相对常规，高频考点是动态规划和贪心算法，难度中等，准备充分的考生通过率不错。

| 公司 | 出题偏好 | 高频考点 | 难度 |
|------|----------|----------|------|
| 字节 | 算法题为主，梯度明显 | 边界处理、动态规划 | 中高 |
| 腾讯 | 偏工程化，单选广 | 网络、操作系统 | 中 |
| 阿里 | 少而精，多考点叠加 | 树、逻辑题 | 高 |
| 美团 | 常规为主 | 动态规划、贪心 | 中 |

智力题怎么应对？核心是"结构化思考"。常见的智力题类型有：概率题、逻辑推理题、数学题、脑筋急转弯。遇到智力题不要慌，先明确题目条件，把问题拆解成小问题，用穷举或递推的方式找规律。比如经典的"100层楼两个鸡蛋"问题，核心不是鸡蛋，而是"用最少的尝试次数确定临界楼层"，本质是动态规划思想。答题时把思考过程写出来，即使答案不对，清晰的思路也能得分。

> 大厂笔试风格各异，但底层考察的东西一样：你的算法基本功和思维习惯——投谁家，就先摸谁的题风。

## 2.6 笔试平台与环境准备：细节决定成败

笔试环节翻车最多的不是题目，而是环境。这一节把平台规则和环境准备讲透，帮你避开最冤的挂法。

先讲平台规则。国内主流笔试平台（牛客网、赛码网、智联招聘笔试、北森等）各有各的规则：有的支持本地IDE调试，有的只能用网页编辑器；有的允许复制粘贴，有的禁止；有的会记录你的粘贴行为。这些规则在笔试邀请邮件或平台公告里都有说明，考前一定要读一遍。特别提醒：很多平台禁止在答题页面使用翻译软件、禁止打开其他网页查资料——即使你不作弊，浏览器里有搜索记录也可能被标记。

再讲环境准备清单。网络：提前测试网速和稳定性，用有线网络比无线更稳，准备手机热点作为备用。设备：笔记本电脑优先，屏幕够大；摄像头和麦克风提前测试，权限提前授权；充电器插好，别让电量成为隐患。软件：浏览器用平台指定的版本，关闭所有弹窗拦截和翻译插件；本地IDE提前装好、配好编译环境，多语言的同学把默认语言设置好。桌面：清理桌面文件，关闭无关应用，把手机放远一点——切屏记录不分你是看消息还是误触，一律计入。

还有一个容易忽略的点：时间窗口。笔试通常有固定的开始时间和时长，迟到十五分钟以上可能无法进入。设好闹钟，提前二十分钟坐到电脑前。如果笔试是"收到链接后四十八小时内任意时间完成"的模式，千万别拖到最后一小时——万一中间网络出问题，连补救的时间都没有。

> 笔试环境的准备清单：网络、设备、权限、桌面、时间——五项全过，才能安心答题。

## 2.7 笔试后的复盘模板：每次必填的六栏表格

笔试后的复盘，是拉开差距的关键动作。不会复盘的人，挂十场还是同样的错；会复盘的人，挂三场就能摸清自己的问题模式。

推荐一个简单的六栏复盘模板，每场笔试后趁记忆新鲜填完：第一栏，场次信息：公司、平台、日期、题型分布；第二栏，得分预估：各题型的得分情况，哪部分拿分、哪部分失分；第三栏，卡壳点：哪道题卡住了、卡在哪里（审题、思路、边界、复杂度）；第四栏，归因：卡壳的根本原因是什么（知识盲区、练习不足、紧张、时间分配）；第五栏，改进动作：针对归因写一条具体可执行的改进（如"补练滑动窗口五道题""笔试前先做平台模拟题"）；第六栏，复用经验：这场笔试有什么值得带走的经验（如"这道题用到了前缀和思想，记入套路库"）。

复盘表攒够五场，就能看出规律：如果你的卡壳点集中在动态规划，说明这块需要系统补练；如果集中在审题，说明需要训练读题习惯；如果场场都是时间不够，说明需要调整做题顺序。规律的发现，就是复盘的回报。

> 复盘不是记录，是提炼——每场笔试留一条可执行的改进动作，十场之后你就是另一个人。

## 2.8 笔试的隐藏规则：部分得分与判分逻辑

很多人以为笔试是"全对才得分"，其实大部分平台是部分得分制，理解判分逻辑能帮你多拿分。

编程题的判分逻辑通常是：题目附带了若干组测试用例，每组用例有对应的分值（用例越多，说明覆盖的场景越全），你的代码通过几组用例就得几分。这意味着：即使你的解法不是最优解、即使你的代码只通过了部分用例，也能拿到对应的分数。所以"写了一半的代码"和"空着"的差别，可能是一道题百分之六十的分数。

基于这个逻辑，有三个实用的得分策略。第一，暴力解法优先：拿到题先想暴力解法，先把用例跑通拿基础分，再想优化。暴力解法能过百分之六十到八十的用例，比纠结最优解导致超时强。第二，留痕策略：即使最终没写出来，也要把思路、部分代码、甚至伪代码写上去——有的平台会看你的答题过程，有思路的痕迹可能多给几分。第三，特判得分：有些题目的部分用例很简单（比如空输入、只有一个元素），针对这些简单用例写特判代码也能拿分。

单选题的判分逻辑也有讲究：大部分平台单选选错不扣分（只得零分），多选题选错可能倒扣（选错扣分、漏选得部分分）。面对多选题，不确定的选项宁可不选——漏选只丢部分分，错选可能把已有的分也倒扣掉。这个规则务必在考前确认，不同平台规则不同。

> 笔试的得分逻辑是"拿分最大化"——暴力解、留痕、特判、保守多选，四个策略叠加，总分能上一个台阶。

## 本篇小结

笔试是第一道大规模淘汰闸门，但它也是最"公平"的环节——规则透明、套路固定、可以靠准备大幅提升通过率。回顾本篇要点：流程上，提前半小时做环境检测，别让摄像头和网络坑了你；机制上，理解切屏检测和代码查重的原理，别踩作弊红线；策略上，先易后难、按分值分配时间，暴力解法过部分用例也是分；能力上，建立算法套路库，审题圈关键词、主动测边界、先估复杂度。
