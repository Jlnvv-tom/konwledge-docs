# 通用型 AI Agent 与对话助手——从"能聊"到"能干"的产品跃迁

你以为 AI 还停留在聊天阶段？其实 2026 年的 AI Agent 已经能帮你订机票、写代码、做财务报表了。

我是怕浪猫，一个在 AI 领域深耕多年的技术人。从 2023 年 ChatGPT 横空出世，到 2026 年 Manus 被 Meta 数十亿美元收购，我亲历了 AI 产品从"能聊"到"能干"的完整跃迁。这个系列《智能体产品全景手册》会带你系统性地认识全球所有主流的智能体产品，从对话助手到具身智能，从开发框架到行业落地，一共 10 篇，每篇 1 万字以上，建议收藏后慢慢看。

这一篇是系列第 1 章，我们从最基础的开始：通用型 AI Agent 和对话助手。

## 1.1 从 ChatGPT 到 Manus：AI 产品进化的三个阶段

要理解今天 AI Agent 的格局，得先看清楚这三年的进化路径。我把 2023 到 2026 年的 AI 产品发展分成三个阶段，每个阶段的核心能力都有本质区别。

**第一阶段：对话生成期（2023-2024 年中）**

这个阶段的标志性产品是 ChatGPT。核心能力是"你问我答"，模型根据训练数据生成文本。它能写文章、能翻译、能写代码片段，但本质上是一个"语言模型"——它只能生成文字，不能执行操作。

这个阶段的局限很明显：你问它"帮我订一张明天去上海的机票"，它能告诉你怎么订，但不能帮你订。它没有手，只有嘴。

> AI 产品的第一阶段，是把搜索引擎的"找答案"变成了"生成答案"，但答案还是停在屏幕上的文字。

**第二阶段：工具调用期（2024 年中-2025 年初）**

这个阶段的关键变化是 Function Calling（函数调用）和 Tool Use（工具使用）的普及。模型不再只是生成文字，而是能调用外部 API、执行代码、访问网络。

Claude 推出了 Computer Use（计算机使用）能力，能直接操作电脑桌面。OpenAI 推出了 GPTs 和 GPT Store，让用户能给 ChatGPT 配置工具。Google 的 Gemini 开始深度集成 Google 搜索和 Workspace。

这个阶段的突破在于：AI 有了"手"，能操作工具了。但每个任务都需要人一步步指挥，AI 不会自己规划。

**第三阶段：自主执行期（2025 年初至今）**

2025 年 1 月，OpenAI 发布 Operator。2025 年 3 月，Manus 横空出世。这标志着 AI 产品进入第三阶段：Agent 能理解你的意图，自己规划步骤，自己调用工具，自己验证结果，最后把成品交付给你。

 Manus 不需要你告诉它"先打开浏览器，再搜索航班，再填写表单"，你只需要说"帮我规划一个下周去东京的三天行程并预订好机票酒店"，它会在云端自主完成整个流程。

> 从"生成式能力"到"Agent 行动力"，这是 2025 年最根本的范式转变。AI 不再是工具，而是变成了会使用工具的工人。

为了更直观地理解三个阶段的差异，我用一张表格来对比：

| 维度 | 第一阶段（对话生成） | 第二阶段（工具调用） | 第三阶段（自主执行） |
|------|-------------------|--------------------|--------------------|
| 核心能力 | 文本生成 | 单步工具调用 | 多步自主执行 |
| 人机交互方式 | 一问一答 | 指令驱动 | 意图驱动 |
| 任务完成度 | 给出建议 | 执行单步操作 | 端到端交付 |
| 典型产品 | ChatGPT 3.5 | GPT-4 + Tools | Manus、Operator |
| 自主程度 | 无 | 低（需逐步指挥） | 高（自主规划+验证） |

2026 年的行业数据也印证了这个趋势。全球 79% 的组织已启动 AI Agent 部署，市场规模达 113 亿美元，同比增长 122%。2026 Q1 全球 AI Agent 融资超 50 亿美元。这不再是概念，而是真金白银的商业化。

## 1.2 通用型自主执行 Agent 深度拆解

通用型自主执行 Agent 是第三阶段的代表性产品。它们不局限于某个垂直领域，而是能处理跨领域的复杂任务。这一节我们来逐一拆解五款核心产品。

### Manus（Monica.im）

Manus 是由中国创业团队 Monica.im 开发的全球首款通用型自主 AI Agent。创始人肖弘带领团队在 2025 年 3 月发布了这款产品，发布后立刻引爆全球科技圈。

Manus 的核心架构采用多智能体协作模式，包含三个关键角色：

**规划器（Planner）**：负责理解用户的意图，将复杂任务拆解为可执行的子任务列表。比如用户说"帮我分析这份财报并生成投资建议"，规划器会拆解为：读取财报文件、提取关键财务指标、对比行业数据、生成分析报告、输出投资建议。

**执行器（Executor）**：按照规划器输出的任务列表，逐个调用工具执行。工具包括浏览器、代码沙箱、文件操作、API 调用等。

**验证器（Verifier）**：每个子任务完成后，验证器检查结果是否符合预期。如果发现问题，会反馈给规划器重新调整方案。

这个架构的核心原理可以用下面的伪代码来表达：

```
function manus_agent(user_intent):
    plan = planner.decompose(user_intent)
    results = []
    for step in plan:
        result = executor.execute(step)
        if verifier.validate(result, step.expected):
            results.append(result)
        else:
            plan = planner.adjust(step, result, plan)
    return synthesize(results)
```

Manus 的产品表现令人瞩目。在 GAIA（General AI Assistants）基准测试中，Manus 刷新了所有难度级别的 SOTA（State of the Art，当前最优）成绩。发布后邀请码一度被炒至 5 万元人民币。2025 年 12 月，Meta 以数十亿美元收购了 Manus，成为 Meta 历史上第三大收购案。

> Manus 证明了一件事：通用型 AI Agent 不是实验室玩具，而是可以交付真实工作成果的生产力工具。

### OpenAI Operator

OpenAI 在 2025 年 1 月发布 Operator，标志着这家公司从对话型 AI 正式转向行动型 AI。

Operator 的核心能力是自主执行浏览器操作。它结合了 GPT 模型的推理能力与浏览器自动化技术，能够完成预订旅行、电商购物、填写表单等任务。与传统的 RPA（Robotic Process Automation，机器人流程自动化）不同，Operator 不需要预先录制操作流程，它能根据自然语言指令自主决定操作步骤。

OpenAI 同步推出了三档付费 Agent 服务，最高定价 2 万美元/月。这个定价策略说明 OpenAI 将 Agent 视为企业级高端服务，而非消费级工具。

Operator 的技术架构基于 CUA（Computer Use Agent，计算机使用智能体）范式，核心流程是：

```
# Operator 的核心循环
while task_not_complete:
    screenshot = capture_screen()
    understanding = model.analyze(screenshot, task_context)
    action = model.decide_action(understanding)
    execute(action)
    task_context.update(action_result)
```

这个"截图-理解-决策-执行"的循环是所有 CUA 产品的底层逻辑，后面我们会在第 6 章详细展开。

### AutoGLM（智谱 AI）

AutoGLM 是智谱 AI 推出的自主执行 Agent，它的差异化在于移动端能力和超长步骤操作。

AutoGLM 能在手机端自主执行超过 50 步的长步骤操作。比如"帮我在美团上找一家三里屯附近评分 4.5 以上的火锅店，订一个今晚 6 点的四人桌，然后把预订信息发给张三"。这个任务涉及打开美团 App、搜索、筛选、预订、切换到微信发消息等多个 App 的跨应用操作。

AutoGLM 的技术核心是多模态理解与 GUI（Graphical User Interface，图形用户界面）交互。它需要理解手机屏幕上的视觉元素（按钮、文本框、图片），然后生成精确的触摸操作（点击坐标、滑动方向、输入文本）。

2025 年，AutoGLM 持续升级，推出了 AgentGLM-PC 版本，支持 Mac 和 Windows 桌面端。智谱 AI 同时开源了 GLM 系列模型，在学术和多语言领域建立了差异化优势。

> 50 步的连续操作意味着什么？意味着 Agent 不是在"执行命令"，而是在"完成项目"。这是质的飞跃。

### Lovart

Lovart 是一款垂直领域的通用型 Agent，专注于创意设计工作流。2025 年 5 月发布后在 X（原 Twitter）上爆火，被称为"设计领域的 Manus"。

Lovart 采用 MCoT（Multi-chain Chain of Thought，多链思维）技术。传统的 Chain of Thought（思维链）是线性的：A 推导到 B，B 推导到 C。而 MCoT 允许同时维护多条推理链，在设计过程中动态调整逻辑分支。比如设计一个品牌 Logo 时，Lovart 会同时探索"极简风格"、"几何风格"、"字体驱动"三条路线，根据用户反馈动态收敛。

Lovart 实现了从需求理解到设计交付的完整闭环：用户说"帮我设计一个咖啡品牌的 Logo，风格温暖、复古"，Lovart 会分析品牌调性、生成多个方案、根据反馈迭代、最终输出可用的高分辨率设计文件。

### OpenHands（原 OpenDevin）

OpenHands 是开源社区驱动的通用型 AI Agent，原名为 OpenDevin。它被视为 Manus 的开源替代方案。

OpenHands 能自主完成软件开发任务，支持代码编写、调试、测试的全流程。它的架构同样采用规划器+执行器模式，但与 Manus 不同的是，OpenHands 更专注于软件开发领域，内置了代码执行沙箱、Git 操作、测试框架等开发工具。

GitHub 上 OpenHands 是高星项目，拥有活跃的开源社区。它的价值在于降低了 AI Agent 的使用门槛——任何人都可以免费部署和修改。

| Manus | Monica.im | 通用 | 否 | 多智能体协作架构，GAIA SOTA |
| Operator | OpenAI | 通用 | 否 | 浏览器操作，企业级定价 |

## 1.3 对话助手与大模型产品全景

对话助手是 AI Agent 的"大脑"基座。即使是最先进的自主执行 Agent，其核心推理能力也来自底层大语言模型。这一节我们来系统性地认识全球主流的对话助手产品。

### ChatGPT（OpenAI）

ChatGPT 是全球 AI 对话产品的绝对标杆。核心模型为 GPT-4o 和 GPT-5 系列。

核心功能方面，ChatGPT 支持多模态交互（文本、语音、图像、代码），拥有最丰富的插件生态，支持联网搜索、文件分析、代码执行。GPT Store 应用生态让它成为一个平台型产品。Canvas 协作编辑模式提供了实时协作体验。

产品表现上，ChatGPT 全球月访问量达 57.5 亿（2026 年 5 月数据），断层式领跑全行业。每周活跃用户超过 3 亿，App Store 下载量超 1 亿次。

> ChatGPT 的真正护城河不是模型能力，而是它构建的生态——插件、GPT Store、开发者社区形成了一个自我强化的飞轮。

### Claude（Anthropic）

Claude 由 Anthropic 开发，核心模型为 Claude 4 系列（包括 Sonnet 和 Opus 两个版本）。

Claude 的核心优势在于超长上下文理解（200K+ tokens，约 15 万汉字）和安全性。它是 MCP（Model Context Protocol，模型上下文协议）的开创者，这个协议后来成为 Agent 与外部工具"即插即用"的行业标准。Claude 还具备 Computer Use（计算机使用）能力，能直接操作电脑桌面。Artifacts 功能支持实时预览与协作，让代码生成和文档撰写体验更佳。

产品表现方面，Claude 月访问量 9.72 亿（2026 年 5 月），环比增长 15.67%，是增长最快的二线产品。在长文本理解与写作逻辑的自然度上被广泛认为是最优的，学术和科研领域使用率很高。

### Gemini（Google DeepMind）

Gemini 由 Google DeepMind 开发，核心模型为 Gemini 3 Pro。

Gemini 的最大优势是与 Google 生态的深度整合：Google 搜索、YouTube、Workspace、Google Finance 都被串联进来。它支持原生多模态（文本、图像、音频、视频），Deep Research 深度研究功能能 5 分钟生成 46 页学术论文，全局记忆功能让对话有连续性。

月访问量 29.9 亿（2026 年 5 月），环比增长 5.13%。在性能上，Gemini Deep Research 超过 OpenAI Deep Research 40%，但价格只有后者的十分之一。

### DeepSeek（深度求索）

DeepSeek 是中国团队深度求索开发的开源大模型产品，核心模型为 DeepSeek-V3 和 R1 系列。

DeepSeek 的核心特点是 MoE（Mixture of Experts，混合专家）架构。MoE 的原理是将一个大模型拆分为多个"专家"子网络，每次推理只激活其中一部分专家，从而在保持模型容量的同时大幅降低计算成本。

DeepSeek 的核心架构原理可以这样理解：

```
# MoE 架构的核心路由机制
class MoELayer:
    def __init__(self, num_experts, hidden_size):
        self.experts = [Expert(hidden_size) for _ in range(num_experts)]
        self.router = Router(hidden_size, num_experts)

    def forward(self, x):
        # 路由器决定激活哪些专家
        gate_scores = self.router(x)  # [batch, num_experts]
        top_k_experts = select_top_k(gate_scores, k=2)
        
        # 只有被选中的专家参与计算
        output = sum(expert(x) * gate_scores[i] 
                     for i, expert in enumerate(top_k_experts))
        return output
```

这种架构让 DeepSeek 以 1/10 的训练数据量在 STEM（Science, Technology, Engineering, Mathematics，科学、技术、工程、数学）领域超越了通用模型，2025 年 1 月爆火后月访问量达 2.78 亿，引发了全球开源 AI 浪潮。

### Kimi（月之暗面）

Kimi 由月之暗面（Moonshot AI）开发，核心差异化是超长上下文窗口，支持 200 万字（约 300 万 tokens）的上下文。

200 万字意味着什么？你可以一次性把一整本书、几十篇论文、或者几百页的财报扔给 Kimi，让它统一分析。这在知识密集型场景（法律文书审查、学术论文阅读、财务报告分析）中极为实用。

Kimi+ 是其智能体平台，用户可以创建和使用特定场景的智能体。Kimi 在长文档分析和学术论文阅读场景的表现是目前国内最好的。

### 豆包（字节跳动）

豆包是字节跳动推出的 AI 对话助手，核心模型为豆包大模型。

豆包的策略是"免费+生态联动"。它与抖音、今日头条的生态打通，用户在抖音内就能直接使用豆包。免费使用策略让用户增长非常迅速，在国内用户规模处于第一梯队。

### 通义千问（阿里云）

通义千问由阿里云开发，核心模型为 Qwen 系列。

通义千问的差异化在于企业级部署支持和多语言能力。AgentStudio 提供智能体开发能力，与阿里云生态深度整合。在市场表现上，千问大模型的企业级调用量占中国市场 32.1%，排名第一。开源版本也受到开发者欢迎。

### 智谱清言 / GLM（智谱 AI）

智谱清言由智谱 AI 开发，核心模型为 GLM-4 系列。

智谱的优势在于多语言和学术领域。AutoGLM 自主智能体已在前文介绍。智能体中心平台让用户可以创建和分享智能体。开源 GLM 系列模型在学术界有广泛影响。

### 文心一言 / 文小言（百度）

文心一言由百度开发，核心模型为文心大模型 4.0。

百度是国内最早推出 AI 对话产品的公司。文小言是其"新搜索"智能助手，支持模糊提问、边拍边问等功能，与手机百度深度整合。AgentBuilder 智能体平台支持企业构建定制 Agent。

### 腾讯元宝

腾讯元宝由腾讯开发，核心模型为混元大模型。

元宝的核心优势是与微信生态的联动。元器智能体平台支持创建和分享智能体，通过微信公众号、QQ 等渠道分发。

### MiniMax（稀宇科技）

MiniMax 由稀宇科技开发，核心模型为 abab 系列。

MiniMax 在创意写作和角色扮演赛道快速崛起。星野智能体社区聚集了大量创作者。语音合成能力也是其亮点，在 AI 语音领域有差异化竞争力。

### Perplexity AI

Perplexity 是 AI 搜索引擎与对话助手的融合产品。

核心功能包括实时引用来源、Deep Research 深度研究、Pro Search 多步推理搜索。在专业人士和学生群体中广泛使用。Deep Research 测试得分 21.1%，超越 Gemini Thinking。

## 1.4 核心能力对比：多模态、长上下文、工具调用、推理能力

上一节我们列了产品，这一节我们来对比能力。对于用户来说，选 AI 助手不是选品牌，而是选能力。四个核心维度决定了 AI 助手能做什么、做多好。

### 多模态能力（Multimodal）

多模态是指模型能同时处理文本、图像、音频、视频等多种输入形式。2026 年的主流大模型都已支持多模态，但能力深度差异很大。

Gemini 在多模态方面最强。它是原生多模态架构，从训练阶段就同时处理文本、图像、音频和视频，而不是后期拼接。这意味着它能理解视频中的动作序列、音频中的情感语调、图像中的空间关系。

ChatGPT 紧随其后，支持文本、语音、图像的输入，但视频理解能力相对弱。

Claude 的多模态能力集中在图像理解（可分析图表、截图、照片），但不支持音频和视频的直接输入。

国产产品中，豆包和通义千问支持文本和图像，但在视频和音频理解方面仍在追赶。

### 长上下文窗口（Long Context）

长上下文窗口决定了模型一次能处理多少信息。这在长文档分析、代码库理解、多轮对话记忆等场景中至关重要。

| 产品 | 上下文窗口 | 约等于 |
|------|-----------|--------|
| Kimi | 200 万字 | 3 本长篇小说 |
| Claude | 200K tokens | 15 万汉字 |
| Gemini | 1M+ tokens | 75 万汉字 |
| ChatGPT | 128K tokens | 9.6 万汉字 |
| DeepSeek | 128K tokens | 9.6 万汉字 |

Kimi 在上下文长度上遥遥领先，200 万字可以一次性处理整套法律法规或者一个完整代码仓库。但上下文长度不等于理解质量——在 200K tokens 以内，Claude 的理解质量被公认最好。

> 上下文窗口就像工作台的大小。台子越大能放的东西越多，但能不能找到、能不能用好，还是看手艺。

### 工具调用能力（Tool Use / Function Calling）

工具调用是 AI Agent 的基础能力。模型通过 Function Calling（函数调用）机制，将自然语言指令转化为对外部 API 的调用。

工具调用的核心原理是：模型接收用户的自然语言请求，判断需要调用哪些工具，生成结构化的调用参数（通常是 JSON 格式），执行调用后将结果整合到回答中。

```
// Function Calling 的核心流程
// 1. 用户发出请求
user: "北京明天天气怎么样？"

// 2. 模型判断需要调用天气API，生成调用参数
model generates: {
  "function": "get_weather",
  "parameters": {"city": "北京", "date": "tomorrow"}
}

// 3. 系统执行API调用，返回结果
api_result: {"temp": "32°C", "condition": "晴", "humidity": "45%"}

// 4. 模型整合结果生成自然语言回答
model: "北京明天晴天，气温32°C，湿度45%，适合出行。"
```

ChatGPT 的工具调用最成熟，插件生态最丰富。Claude 通过 MCP 协议实现了工具的标准化接入。Gemini 与 Google 服务（搜索、地图、日历）深度集成。国产产品中，通义千问和智谱的工具调用能力较强。

### 推理能力（Reasoning）

推理能力是指模型在复杂逻辑、数学、科学问题上的表现。2025 年以来，推理能力成为大模型竞争的核心战场。

OpenAI 的 o 系列模型（o1/o3）和 DeepSeek 的 R1 模型采用了 RL（Reinforcement Learning，强化学习）+ CoT（Chain of Thought，思维链）的训练方法，在 STEM 领域表现突出。这种方法的原理是让模型在给出答案前先"思考"——生成中间推理步骤，然后逐步推导到最终答案。

Claude 在逻辑推理和代码推理方面表现优秀。Gemini 在数学和科学推理上有优势。DeepSeek R1 以低成本实现了顶尖推理性能，是开源推理模型的标杆。

## 1.5 选型指南：不同场景下该选哪个 AI 助手

讲了这么多产品和能力，最后来点实用的。不同场景下到底该选哪个？我根据使用场景做了 5 个选型决策。

**场景一：日常对话与内容创作**

首选 ChatGPT 或 Gemini。ChatGPT 的综合能力最均衡，适合各种类型的对话和创作。Gemini 在需要联网信息和多模态理解时更有优势。如果主要用中文，豆包和通义千问也是不错的选择，免费且本地化好。

**场景二：长文档分析与学术研究**

首选 Claude 或 Kimi。Claude 在 200K tokens 以内的理解质量最好，写作逻辑最自然。Kimi 在超长文档（200 万字）场景无可替代。如果你需要读 50 篇论文并做综述，Kimi 是唯一能一次性处理的。如果需要深度理解单篇论文的逻辑，Claude 更好。

**场景三：编程辅助**

首选 Claude 或 ChatGPT。Claude 在代码逻辑理解和长代码生成方面最强。ChatGPT 的代码执行能力和工具生态更好。如果是中文编程场景，通义灵码和 CodeGeeX 是国产首选。编程 Agent 的详细对比我们会在第 4 章展开。

**场景四：企业部署与数据安全**

首选通义千问或 DeepSeek。两者都支持私有化部署，通义千问在中国企业级市场调用量第一。DeepSeek 开源且成本低，适合预算有限的企业。如果需要在全球范围部署，Claude 和 Gemini 的多语言能力更强。

**场景五：自主任务执行**

首选 Manus 或 OpenAI Operator。Manus 在通用任务执行和 GAIA 测试中表现最好。Operator 在浏览器操作和企业级场景有优势。如果需要移动端操作，AutoGLM 是唯一成熟的选择。预算有限可以尝试 OpenHands 开源方案。

为了方便收藏，我把选型决策整理成一张速查表：

| 使用场景 | 首选产品 | 备选产品 | 选择理由 |
|---------|---------|---------|---------|
| 日常对话创作 | ChatGPT | Gemini、豆包 | 综合能力最均衡 |
| 长文档分析 | Claude | Kimi | 理解质量最高 |
| 超长文档处理 | Kimi | - | 200万字上下文 |
| 编程辅助 | Claude | ChatGPT | 代码逻辑最强 |
| 企业私有部署 | 通义千问 | DeepSeek | 企业级支持+市场份额 |
| 自主任务执行 | Manus | Operator | GAIA SOTA |
| 移动端操作 | AutoGLM | - | 50+步跨App操作 |
| AI 搜索研究 | Perplexity | Gemini | 实时引用+免费DR |
| 开源本地部署 | DeepSeek | OpenHands | 开源+低成本 |
| 多模态理解 | Gemini | ChatGPT | 原生多模态 |
