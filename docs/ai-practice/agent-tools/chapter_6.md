# 计算机操作智能体与 RPA 超自动化——AI 接管你的屏幕

AI 直接操作你的电脑，订机票、填报表、回邮件，这不是科幻，这是 2026 年的日常。

我是怕浪猫，《智能体产品全景手册》第 6 篇。这一篇我们讲一个最"硬核"的 Agent 赛道：Computer Use Agent（CUA，计算机使用智能体）和 RPA（Robotic Process Automation，机器人流程自动化）。当 AI 从"生成文字"进化到"操作界面"，数字世界的劳动力结构正在被重写。

## 6.1 CUA 核心原理：截图-理解-决策-执行循环

Computer Use Agent 的核心理念很简单：像人类一样使用电脑。人类怎么操作电脑？看屏幕、理解内容、决定操作、执行操作。CUA 用完全相同的方式操作电脑。

这个"截图-理解-决策-执行"循环是所有 CUA 产品的底层逻辑，理解了这个循环就理解了 CUA 的本质。

### 步骤一：截图（Screen Capture）

CUA 的第一步是获取屏幕画面。它不是读取应用的 API 或 DOM（Document Object Model，文档对象模型），而是直接截取屏幕图像。这就像人类看屏幕一样——你看到的是像素，不是代码。

截图的方式有多种：截取整个屏幕、截取特定窗口、截取特定区域。高级的 CUA 还支持多显示器截屏。

为什么选择截图而不是读取 API 或 DOM？因为截图是最通用的方式。不管是网页、桌面应用、还是远程桌面，截图都能工作。API 和 DOM 方式需要针对每个应用单独适配，而截图方式一套方案通吃所有应用。

### 步骤二：理解（Understanding）

获取截图后，CUA 用多模态大模型（如 GPT-4o、Claude 4）分析图像内容。模型需要识别出屏幕上的 UI 元素：按钮、输入框、下拉菜单、复选框、链接、文本内容等。

这个步骤是 CUA 最难的部分。因为屏幕上的 UI 元素千变万化——不同应用有不同的设计风格、布局、字体、颜色。模型需要像人一样理解"这个蓝色的矩形是一个按钮，点击它会打开新页面"。

理解阶段不仅识别元素，还要理解元素之间的关系和当前页面的状态。比如"这个表单需要填写用户名和密码，然后点击登录按钮"。

### 步骤三：决策（Decision）

理解了屏幕内容后，CUA 需要决定下一步操作。决策依据包括：用户的目标、当前屏幕状态、之前已执行的操作。

比如用户的目标是"在携程订一张明天去上海的机票"。CUA 的决策链可能是：

1. 当前在浏览器首页 → 决定打开携程网站
2. 在携程首页 → 决定在搜索框输入"北京到上海"
3. 搜索结果页面 → 决定选择明天的航班
4. 航班列表 → 决定选择最便宜的那个
5. 订单页面 → 决定填写乘客信息
6. 填写完成 → 决定点击提交按钮

每一步决策都需要模型基于当前截图和目标任务推理出最优操作。

### 步骤四：执行（Action）

决策完成后，CUA 执行具体的操作。常见操作类型包括：

**点击（Click）**：点击屏幕上的特定坐标。CUA 需要精确定位 UI 元素的位置。

**输入（Type）**：在输入框中输入文本。CUA 需要先点击输入框使其获得焦点，然后输入文字。

**滚动（Scroll）**：上下或左右滚动页面。

**键盘快捷键（Hotkey）**：如 Ctrl+C 复制、Ctrl+V 粘贴、Alt+Tab 切换窗口。

**拖拽（Drag & Drop）**：拖动元素到目标位置。

```
# CUA 核心循环的完整实现
class ComputerUseAgent:
    def __init__(self, vision_model, action_executor):
        self.vision = vision_model    # 多模态视觉模型
        self.executor = action_executor  # 操作执行器
        self.history = []              # 操作历史
    
    def run(self, goal, max_steps=50):
        for step in range(max_steps):
            # 1. 截图
            screenshot = self.capture_screen()
            
            # 2. 理解屏幕内容
            understanding = self.vision.analyze(
                image=screenshot,
                task=goal,
                history=self.history
            )
            # understanding = {
            #     "elements": [
            #         {"type": "button", "text": "搜索", "position": [320, 450]},
            #         {"type": "input", "label": "出发地", "position": [100, 200]},
            #         {"type": "text", "content": "携程旅行网", "position": [50, 50]}
            #     ],
            #     "page_type": "flight_search",
            #     "current_state": "搜索结果页面"
            # }
            
            # 3. 决策下一步操作
            action = self.vision.decide(
                understanding=understanding,
                goal=goal,
                history=self.history
            )
            # action = {
            #     "type": "click",
            #     "position": [320, 450],
            #     "reasoning": "搜索框已输入出发地和目的地，点击搜索按钮查看航班"
            # }
            
            # 4. 检查是否完成任务
            if action["type"] == "complete":
                return action["result"]
            
            # 5. 执行操作
            self.executor.execute(action)
            
            # 6. 记录历史
            self.history.append({
                "step": step,
                "screenshot": screenshot,
                "understanding": understanding,
                "action": action
            })
        
        return {"status": "max_steps_reached", "history": self.history}
```

> CUA 的哲学是"模拟人类"。人类不需要 API 就能用软件，CUA 也不需要。这意味着任何人类能操作的软件，CUA 理论上都能操作。

### CUA 的技术挑战

CUA 看起来简单，实际实现有很多技术挑战：

**挑战一：元素定位精度**。屏幕上的按钮可能只有 20x20 像素，CUA 需要精确定位到这个位置才能点击。视觉模型的坐标定位精度直接决定了 CUA 的可用性。

**挑战二：动态内容处理**。网页内容会动态加载，弹窗可能突然出现，页面可能重定向。CUA 需要实时感知这些变化并调整策略。

**挑战三：长步骤任务**。订一个机票可能需要 20 步操作，每一步都必须正确。如果第 15 步出错，CUA 需要知道如何回退或修正。50+ 步的操作链是目前的极限。

**挑战四：验证码和反爬**。很多网站有 CAPTCHA（Completely Automated Public Turing test to tell Computers and Humans Apart，完全自动化公共图灵测试）验证码，这是专门为了区分人类和机器的。CUA 操作网站时经常遇到这个障碍。

## 6.2 Claude Computer Use vs OpenAI Operator vs AutoGLM-PC

上一节讲了 CUA 的原理，这一节来对比三款桌面端 CUA 产品的差异化。

### Claude Computer Use（Anthropic）

Claude Computer Use 是 Anthropic 在 2024 年 10 月推出的功能，让 Claude 能直接操作电脑桌面。

核心特色：

**安全优先**：Claude 的 CUA 在执行任何可能有风险的操作前（如删除文件、发送邮件、提交订单）会暂停并请求用户确认。这是 Anthropic 一贯的安全理念。

**开发友好**：Claude 提供了完整的 API，开发者可以在自己的应用中集成 Computer Use 能力。API 设计清晰，文档完善。

**桌面控制范围**：支持截屏、鼠标点击、键盘输入、滚动等全范围操作。能操作浏览器、文件管理器、终端等桌面应用。

Claude Computer Use 的典型应用场景是企业自动化——在 CRM 系统中录入数据、在 ERP 系统中生成报表、在邮件客户端中批量回复。由于 Claude 的长文本理解能力最强，在需要阅读大量文本后做操作的场景（如阅读合同后填写审批表）表现最好。

### OpenAI Operator

OpenAI Operator 在第 1 章已经介绍过其基本能力，这里从 CUA 技术角度补充分析。

Operator 的技术特色在于**自主规划能力**。当用户给出一个目标后，Operator 不只是逐步执行，而是先生成一个完整的执行计划，然后按计划执行。如果中间某步失败，它能重新规划。

Operator 的另一个特色是**浏览器专注**。与 Claude Computer Use 的全桌面控制不同，Operator 主要在浏览器中操作。这意味着它不需要控制整个桌面，降低了复杂度和安全风险。但同时也限制了它的能力——不能操作桌面应用。

在商业模式上，Operator 定位为企业级服务，最高 2 万美元/月。这个定价意味着 OpenAI 将 Operator 定位为高端企业工具，而非消费级产品。

### AutoGLM-PC（智谱 AI）

AutoGLM-PC 是智谱 AI 推出的桌面端 CUA，是 AutoGLM 移动端的桌面版本。

核心特色：

**中文环境优化**：在中国软件生态（微信、钉钉、飞书、WPS、各种国产 ERP/OA）中的操作表现优于国际产品。这是因为训练数据中包含了大量中文软件界面。

**移动端+桌面端协同**：AutoGLM 同时支持手机端和桌面端。你可以在手机上给 AutoGLM 发指令，它在电脑上执行操作。这种跨设备协同是独特的。

**50+ 步长操作**：AutoGLM 能执行超过 50 步的连续操作链，这是目前所有 CUA 产品中最长的。长步骤操作的关键不只是技术能力，还有错误恢复能力——50 步中任何一步出错都不能前功尽弃。

### 三款 CUA 的横向对比

| 维度 | Claude Computer Use | OpenAI Operator | AutoGLM-PC |
|------|--------------------|-----------------|------------|
| 控制范围 | 全桌面 | 浏览器 | 全桌面 |
| 规划能力 | 逐步执行 | 先规划后执行 | 混合模式 |
| 安全机制 | 操作前确认 | 企业级权限 | 分级权限 |
| 中文环境 | 一般 | 一般 | 最强 |
| 移动端 | 不支持 | 不支持 | 支持 |
| 长步骤 | ~20步 | ~30步 | 50+步 |
| 商业模式 | API付费 | $200-$20000/月 | 订阅制 |
| 适合场景 | 文本密集型 | 浏览器自动化 | 中文环境 |

> 三款 CUA 各有侧重：Claude 重安全、Operator 重规划、AutoGLM 重中文和长步骤。没有最好的，只有最适合的。

## 6.3 RPA 老兵的 Agent 化：实在 Agent 与传统 RPA 的对比

RPA（Robotic Process Automation，机器人流程自动化）不是新概念。在 AI Agent 出现之前，RPA 已经在企业中应用了十几年。UiPath、Automation Anywhere、Blue Prism 是传统 RPA 的三巨头。

但传统 RPA 和 AI Agent 驱动的新一代 RPA 有本质区别。

### 传统 RPA 的工作方式

传统 RPA 是"录制-回放"模式。开发者通过录制工具记录人类操作软件的步骤（点击哪个按钮、在哪个输入框输入什么、按什么快捷键），然后 RPA 机器人重复执行这些步骤。

传统 RPA 的核心问题：

**脆弱性**：如果软件界面发生任何变化（按钮位置变了、新增了一个弹窗、加载速度变慢），RPA 脚本就会失败。传统 RPA 基于坐标或 DOM 选择器定位元素，一旦界面变化就需要重新录制。

**无智能**：传统 RPA 只能执行固定流程，不能处理异常情况。如果遇到验证码、选择分支、需要判断的场景，RPA 就无能为力。

**高维护成本**：因为软件界面经常变化，RPA 脚本需要频繁更新。大型企业的 RPA 团队经常花 60% 的时间在维护现有脚本上。

### AI Agent 驱动的新一代 RPA

AI Agent 驱动的新一代 RPA（有时称为 Intelligent Process Automation，IPA）用 AI 替代了录制-回放模式。

**视觉理解替代坐标定位**：AI Agent 通过视觉模型理解屏幕内容，不需要精确的坐标或选择器。即使按钮位置变了，AI 也能识别出来。

**自然语言指令替代脚本**：用"把这份报表里的数据录入到 ERP 系统"这样的自然语言替代复杂的脚本代码。

**自主决策替代固定流程**：遇到异常情况（弹窗、验证码、选项判断），AI 能自主决策如何处理，而不是直接报错。

### 实在 Agent（实在智能）

实在 Agent 是实在智能推出的 AI 驱动 RPA 产品，代表了中国 RPA 老兵的 Agent 化转型。

实在智能的核心技术是"塔斯大模型 + RPA"架构。塔斯大模型负责理解用户意图和规划操作步骤，RPA 引擎负责执行具体操作。

产品表现数据很亮眼：将某客户的对账流程从 78 分钟压缩到 4 分钟，差错率降为 0。这种数量级的效率提升是传统 RPA 无法达到的——传统 RPA 也能自动化对账流程，但设置和维护一个对账 RPA 脚本本身就需要数天时间。

实在 Agent 的差异化在于对复杂业务流程的理解能力。它不是简单地"按步骤执行"，而是能理解"为什么要这样做"，当遇到特殊情况时能做出合理判断。

### 传统 RPA vs AI Agent RPA

| 维度 | 传统 RPA | AI Agent RPA |
|------|---------|-------------|
| 工作方式 | 录制-回放 | 意图理解-自主执行 |
| 界面适配 | 坐标/选择器（脆弱） | 视觉理解（弹性） |
| 异常处理 | 报错停止 | 自主决策 |
| 开发方式 | 编写/录制脚本 | 自然语言描述 |
| 维护成本 | 高（界面变化需更新） | 低（视觉理解自适应） |
| 适用场景 | 高频固定流程 | 灵活多变流程 |
| 速度 | 快（直接执行） | 慢（需要AI推理） |
| 准确性 | 高（固定流程） | 中（AI可能出错） |

> 传统 RPA 是"录好的磁带"，AI Agent RPA 是"会弹琴的人"。磁带快但只会一首歌，人慢但什么歌都能弹。

### 两种技术的互补关系

AI Agent RPA 不会完全替代传统 RPA。两者更可能是互补关系：

对于高频、固定、不需要判断的流程（如每天凌晨从 FTP 下载文件、定时备份数据库），传统 RPA 仍然是更好的选择——它更快、更稳定、成本更低。

对于低频、灵活、需要判断的流程（如处理客户投诉邮件、审核报销单据），AI Agent RPA 有明显优势——它能理解内容、做出判断、处理变化。

## 6.4 超自动化（Hyperautomation）与企业级落地

超自动化是 Gartner 提出的概念，指的是"将 AI、RPA、低代码等多种自动化技术组合，实现端到端的业务流程自动化"。

超自动化不是单一技术，而是一个技术栈：

**Layer 1：流程发现**。用 Process Mining（流程挖掘）技术分析企业现有业务流程，找出适合自动化的环节。

**Layer 2：任务执行**。用 RPA 或 CUA 执行重复性操作。

**Layer 3：智能决策**。用 AI Agent 进行判断和决策。

**Layer 4：流程编排**。用工作流引擎串联上述组件，实现端到端自动化。

**Layer 5：监控优化**。持续监控自动化流程的运行状态，优化效率。

### 企业级 CUA 落地的三个关键问题

企业要把 CUA 真正落地，必须回答三个关键问题：

**问题一：安全与权限**

CUA 能操作电脑意味着它有权限访问企业系统。如果 CUA 执行了一个错误操作（如删除了重要数据、发送了错误邮件），后果可能很严重。

解决方案：分级权限控制。低风险操作（如读取数据、生成报告）CUA 可以自主执行。高风险操作（如删除数据、发送外部邮件、提交订单）必须有人工确认环节。

**问题二：可观测性**

当 CUA 自主执行 50 步操作时，你怎么知道每一步是否正确？如果最终结果出错了，你怎么定位是哪一步的问题？

解决方案：完整的操作日志和回放能力。每一步的截图、理解结果、决策推理、执行操作都应被记录。当出错时可以回溯定位。

**问题三：成本与效率的平衡**

CUA 的每一步操作都需要调用视觉模型进行推理，成本不低。如果一个流程每天执行 1000 次，每次 50 步，每天就是 50000 次模型调用。

解决方案：对高频固定流程使用传统 RPA，对低频灵活流程使用 CUA。混合模式是企业的最优选择。

> CUA 在企业落地最大的障碍不是技术，而是信任。让 AI 操作你的电脑，就像让新员工操作你的系统——你需要权限控制、操作日志和逐步放权。

## 6.5 超自动化产品矩阵与企业选型

最后，我们来看超自动化领域的产品矩阵和选型建议。

### 产品矩阵

| 产品 | 类型 | 核心能力 | 适合场景 |
|------|------|---------|---------|
| 实在 Agent | AI RPA | 塔斯模型+RPA | 企业财务、对账 |
| UiPath | 传统 RPA + AI | 流程录制+AI增强 | 大型企业标准化流程 |
| Automation Anywhere | 传统 RPA + AI | 云原生RPA | 中大型企业 |
| Claude Computer Use | CUA API | 桌面控制 | 开发者集成 |
| OpenAI Operator | CUA 服务 | 浏览器自动化 | 企业高端场景 |
| AutoGLM-PC | CUA 应用 | 桌面+移动 | 中文环境 |
| n8n | 工作流自动化 | 400+集成 | 混合编排 |
| 钉钉 AI 助理 | 办公自动化 | 钉钉生态内 | 办公行政 |

### 选型建议

**大型企业、高频标准化流程**：UiPath + AI 增强。UiPath 的流程管理、权限控制、审计日志最成熟。在其基础上叠加 AI 能力处理异常情况。

**中型企业、灵活流程**：实在 Agent 或 n8n + CUA。实在 Agent 在中文环境有优势，n8n 在集成灵活性上更强。

**个人用户、轻量自动化**：AutoGLM-PC 或 n8n 社区版。AutoGLM 适合中文环境，n8n 适合连接多个在线服务。
