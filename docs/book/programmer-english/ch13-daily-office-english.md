# 第十三章：外企日常办公英语

> 进入外企，技术能力只是入场券，真正的日常是从一个个看似不起眼的沟通场景开始的——站会上的一分钟发言、Sprint Planning 上的一句提问、1-on-1 里和 manager 的一次深谈。这些场景看似简单，但对非母语者来说，每一个都是"知道该说什么但不知道用英语怎么说"的高频痛点。本章带你逐一攻破外企日常办公中最常见的七类沟通场景，每个场景都配备大量可直接套用的英文模板，让你在任何会议里都能开口不慌。

---

## 13.1 入职第一周常见场景与表达

入职第一周，信息量爆炸：要认人、认系统、认流程、认工具。你可能会觉得自己像个在异国他乡迷路的游客——什么都想问，又怕问太多显得不专业。别担心，这一节帮你准备好第一周最需要的英文表达。

### 自我介绍

入职第一天的自我介绍不需要长篇大论，简洁友好即可。关键信息：名字、角色、之前在做什么、一个个人小细节（拉近距离）。

**标准模板：**

```
Hi everyone, I'm [Name], and I just joined the team as a [Role].
Before this, I was working at [Company/Project] focusing on [Area].
I'm really excited to be here and looking forward to working with you all.
Outside of work, I enjoy [hobby/interest].
```

**实战示例：**

- "Hi everyone, I'm Li Wei, and I just joined the team as a Senior Backend Engineer. Before this, I was at ByteDance working on their recommendation infrastructure. Really excited to be here! Outside of work, I'm a big fan of hiking and board games."

- "Hey folks, I'm Zhang Min — call me Min. I'm the new Frontend Engineer on the Web Platform team. I came from a fintech startup where I built their design system. Happy to join the team! I'm also a coffee nerd, so if anyone wants to do coffee runs, count me in."

**当别人介绍自己时，你可以这样回应：**

- "Nice to meet you, [Name]! Welcome to the team."
- "Great to have you here! I'm [Your Name], working on [Your Area]. Feel free to reach out if you need anything."
- "Welcome aboard! I sit right over there — just flag me down if you have questions."

### 询问权限与账号

第一周你大概率需要各种权限：代码仓库访问、部署平台登录、内部工具账号等。下面是高效请求权限的表达：

**邮件 / Slack 模板：**

```
Hi [Name],

I'm the new [Role] who just joined the team. I need access to the following systems to get started:

1. [System/Repo name] — for [purpose]
2. [System/Repo name] — for [purpose]
3. [System/Repo name] — for [purpose]

Could you help grant the access when you get a chance? Let me know if you need any additional info from my side.

Thanks,
[Your Name]
```

**Slack 快速版：**

- "Hey [Name], I'm new to the team — could you add me to the [repo/channel/group]? Thanks!"
- "Hi [Name], I'm trying to set up my dev environment. It looks like I don't have access to [system/tool]. Could you help me out?"
- "Quick question — what's the process for getting [tool/platform] access? Do I need to file a ticket or can someone add me directly?"

### 认人与记名字

外企团队往往跨国、跨时区，名字和面孔对不上是常态。大方地确认就好，没人会介意。

**实用句型：**

- "Sorry, I'm still learning everyone's names — you're [Name], right? And you work on [Area]?"
- "Could you remind me which team you're on? I want to make sure I'm reaching out to the right person."
- "I'm trying to map out who owns what — would you mind giving me a quick rundown of the team structure?"
- "Who should I talk to about [topic]? I want to make sure I'm pinging the right person."
- "Is there a team wiki or org chart I can reference?"

### 熟悉工具链

每个公司的工具链都不一样，第一周你需要快速搞清楚用什么工具做什么事。

**提问模板：**

| 场景 | 英文表达 |
|------|---------|
| 问代码仓库 | "Where does the [team/project] repo live? Is it on GitHub/GitLab?" |
| 问 CI/CD | "What do we use for CI/CD? Is there a pipeline I should be aware of?" |
| 问部署流程 | "What's the deployment process here? Do I need to create a release ticket?" |
| 问文档系统 | "Where does the team store documentation? Confluence, Notion, or something else?" |
| 问沟通工具 | "Which channels should I join on Slack/Teams? Are there any must-join channels?" |
| 问开发环境 | "Is there a setup guide for the dev environment? I want to make sure I'm not missing anything." |
| 问代码审查流程 | "What's the code review process? Who should I tag as reviewers?" |
| 问任务管理 | "What tool do we use for task tracking? Jira, Linear, or something else?" |

**一段完整的"求助"消息：**

```
Hi team, I'm getting set up this week. I've gone through the onboarding doc
and have a few questions:

1. Is there a standard dev container or should I set up locally?
2. I see we use [Tool A] for CI — is there a doc on how to read the pipeline results?
3. Who's the go-to person for [internal tool/platform] questions?

Happy to hop on a quick call if that's easier. Thanks in advance!
```

### 小贴士：第一周的"三个不要"

1. **不要怕问问题。** 第一周是"问题豁免期"，大家默认你会问很多问题。利用这个窗口期。
2. **不要假装听懂。** 如果别人提到一个你不熟悉的工具或缩写，直接问："Sorry, I'm not familiar with [X] — could you give me a quick overview?" 比后面搞砸了再解释好得多。
3. **不要只问不说。** 适当分享你的背景和经验，让团队了解你能带来什么。这也是建立信任的第一步。

## 13.2 Standup Meeting 发言模板与实战

Standup（站会）是外企研发团队最高频的仪式，通常每天早上进行，时长 15 分钟以内。它的核心是三个问题：昨天做了什么、今天要做什么、有没有遇到阻碍。听起来简单，但要在 1-2 分钟内用英语把信息说清楚、说到位，是需要练习的。

### 经典三段式结构

Standup 的黄金结构就是 **Yesterday → Today → Blockers**：

```
Yesterday: [what you completed]
Today: [what you plan to do]
Blockers: [what's blocking you, or "no blockers"]
```

### 标准模板与示例

**模板一：简洁标准版**

```
Yesterday I worked on [task/ticket], and [completed it / made progress on it].
Today I'm planning to [next task].
No blockers.
```

**实战示例：**

- "Yesterday I finished the API endpoint for user authentication and got the PR merged. Today I'm planning to start on the password reset flow. No blockers."

- "Yesterday I was debugging the memory leak issue in the payment service. I found the root cause — it's related to the connection pool not being released properly. Today I'll write the fix and add a test for it. No blockers."

- "Yesterday I pair-programmed with Sarah on the frontend state migration. We got about 80% done. Today I'll wrap up the remaining components and open a PR for review. No blockers so far."

**模板二：有 Blocker 版**

```
Yesterday I was working on [task], but I ran into [issue].
Today I plan to [plan], but I'm blocked on [blocker].
[Optional: I've already reached out to [person] / Could someone help with [issue]?]
```

**实战示例：**

- "Yesterday I was working on the data export feature, but I ran into a permission issue with the S3 bucket. Today I plan to continue once that's resolved. I've already pinged the DevOps team about it — no other blockers."

- "Yesterday I started integrating the new search API, but I noticed the API docs seem outdated. I'm blocked on getting the correct request schema. Could someone point me to the latest spec or the API owner?"

### 进阶表达：让站会更高效

**当你需要更多时间讨论某个问题时：**

- "I have a question about [topic], but it might take a while. Can we take it offline after standup?"
- "This is going to need a deeper dive — I'll set up a separate meeting to discuss."
- "I can explain more in the team channel after standup if anyone's interested."

**当你接手别人的任务时：**

- "I picked up the ticket from [Name] who's on PTO. I'll be continuing the work on [task]."
- "I'm covering for [Name] this week, so today I'll be looking into [their task]."

**当你在等待别人完成依赖项时：**

- "I'm waiting on [Name] to finish the [component] before I can start on [my task]. I'll work on [other task] in the meantime."
- "I'm blocked on the design review — once [Name] signs off on the UI, I can proceed."

### 常见变体与场景

**远程工作 / 异步 Standup（文字版）：**

很多分布式团队用 Slack 或 Teams 做异步站会，格式更简洁：

```
📋 Daily Update — [Date]
✅ Yesterday: Finished the login refactoring, PR #1234 merged
📍 Today: Starting on the rate limiter implementation
🚫 Blockers: None
```

**当你没有太多进展时（诚实但有策略地表达）：**

- "Yesterday was mostly meetings, so I didn't get much coding done. I did review two PRs though. Today I'll focus on [task]."
- "Yesterday I spent most of my time investigating the [issue] — it turned out to be more complex than expected. I've documented my findings in [doc/link]. Today I'll start implementing the fix."

**当你提前完成任务时：**

- "Yesterday I wrapped up [task] ahead of schedule. I picked up [next task] from the backlog. Today I'll continue on that. No blockers."
- "I finished the spike on [topic] yesterday — wrote up my findings in this doc [link]. Happy to walk anyone through it. Today I'll start on the implementation."

### Standup 常用词汇速查

| 中文 | 英文 | 示例 |
|------|------|------|
| 提 PR | open a PR / submit a PR | "I opened a PR for the auth refactor." |
| 合并 PR | merge a PR | "The PR got merged yesterday." |
| 代码审查 | review a PR | "I reviewed two PRs yesterday." |
| 排查问题 | investigate / look into | "I'm looking into the timeout issue." |
| 修复 bug | fix / patch | "I patched the memory leak." |
| 部署 | deploy / ship | "We shipped the new feature to production." |
| 回归测试 | regression test | "I'm running regression tests before the release." |
| 联调 | integrate / do integration testing | "We're doing integration testing with the mobile team." |
| 技术预研 | spike / investigation | "I did a spike on WebAssembly integration." |
| 结对编程 | pair programming | "I paired with Tom on the database migration." |

### 一句话总结

Standup 的核心不是汇报工作量，而是**同步信息、暴露阻碍、让团队知道你在做什么**。保持简洁，说重点，有 Blocker 及时提——这就是一个优秀的 Standup。

## 13.3 Sprint Planning 与 Backlog Grooming 表达

Sprint Planning 和 Backlog Grooming（也叫 Refinement）是敏捷开发中最核心的两个会议。前者决定"这周做什么"，后者决定"未来几周要准备什么"。在这些会议中，你需要理解需求、估算工作量、提出疑问、认领任务——每一步都需要用到英语。

### 估算工作量（Estimation）

估算通常用 Story Points 或 T-shirt Size（S/M/L/XL）。在 Planning Poker 或讨论环节中，你需要解释自己的估算理由。

**表达估算：**

- "I'd estimate this as a 5 — it involves a new API integration and some data migration."
- "This feels like an 8 to me. The UI looks straightforward, but the backend logic is complex with all the edge cases."
- "I think this is a 3. We've done similar work before, and we have reusable components."
- "I'd put it at a Large. There are too many unknowns right now."

**质疑别人的估算：**

- "I notice you estimated this as a 2, but don't we need to update the database schema as well? That might bump it up."
- "Just to push back a bit — I think this is closer to a 5 given the testing complexity."
- "I'm seeing this as a 5, but you put down a 3. What am I missing? Maybe I'm overestimating the integration work."

**当需求不清晰导致无法估算时：**

- "I can't really estimate this without more details on the expected behavior. Could we write up an acceptance criteria first?"
- "There are too many open questions here. Can we move this back to the backlog and refine it more?"
- "I'd rather not estimate this yet — I need to do a quick spike to understand the current architecture first."

### 提问与澄清需求

在 Sprint Planning 中，理解需求是最关键的一步。不要怕问"蠢问题"——通常其他人也有同样的疑问。

**理解需求：**

- "Just to make sure I understand — the goal of this story is to [restate the requirement], right?"
- "Could you walk through the user flow for this story? I want to make sure I understand the expected behavior."
- "What's the definition of done for this ticket? Does it include [testing / documentation / monitoring]?"
- "Are there any specific performance requirements? Like response time or throughput?"

**质疑需求范围：**

- "This ticket seems to cover a lot of ground. Should we split it into smaller stories?"
- "I think the scope here is a bit ambitious for one sprint. Can we break out the [sub-feature] into a separate ticket?"
- "This overlaps with the work [Name] is doing on [ticket]. Should we consolidate or keep them separate?"
- "Do we really need [feature] for this MVP, or can we defer it to the next sprint?"

**关于优先级：**

- "Is this a must-have for this sprint, or a nice-to-have?"
- "What's driving the priority on this? Is there a customer deadline?"
- "I see this is marked as high priority, but [other ticket] seems more urgent based on the [issue/bug report]. Should we reprioritize?"

### 认领任务（Claiming Tasks）

**主动认领：**

- "I can take this one. I worked on the [related area] before, so I have some context."
- "I'll pick up [ticket]. I've been wanting to learn more about [area]."
- "I'm happy to work on this — I have bandwidth after finishing [previous task]."

**被指派任务时确认：**

- "Sounds good, I'll take it. When's the expected delivery?"
- "Got it. I'll start on this after I wrap up [current task]. Should be able to get to it by [day]."
- "I can do this, but I might need some help with [specific part]. Who's the best person to reach out to?"

**当你已经有太多任务时：**

- "I'd love to help, but my plate is pretty full this sprint with [task A] and [task B]. Can someone else take it, or should we push it to next sprint?"
- "I don't think I can commit to this one. I'm already at capacity with the [feature] work."
- "If I take this on, something else has to give. Which of my current tickets is lower priority?"

### Backlog Grooming / Refinement 表达

Backlog Refinement 是对未来的需求进行预加工，让它"ready for sprint"。

**拆分大任务：**

- "This epic is too big. Let's break it down — I'd suggest splitting it into [A], [B], and [C]."
- "Can we extract the [sub-feature] into its own story? It's independent enough to be worked on separately."
- "I think we should split this horizontally — backend and frontend as separate stories. Different people will work on them."

**补充验收标准：**

- "We need acceptance criteria for this story. What's the expected behavior when [edge case]?"
- "I'd add a criterion for error handling — what should happen if the API times out?"
- "Should we include accessibility testing in the acceptance criteria?"
- "What about backward compatibility? Do we need to support the old API version during the transition?"

**识别依赖：**

- "This story depends on [team's] API being ready. Has that been communicated?"
- "We can't start on this until [infrastructure change] is done. Should we flag that as a blocker?"
- "There's a cross-team dependency here — we need the Platform team to provision the new environment first."

### Sprint Planning 常用短语速查

| 场景 | 英文表达 |
|------|---------|
| 确认容量 | "What's our capacity this sprint? Is anyone on PTO?" |
| 确认目标 | "What's the sprint goal? What are we trying to deliver?" |
| 标记风险 | "I see a risk with [task] — if [thing] doesn't go as planned, it could block the whole sprint." |
| 建议延后 | "Can we move this to the next sprint? It's not time-critical." |
| 确认就绪 | "Is this story ready? Do we have enough detail to start?" |
| 提出技术债 | "Should we allocate some points for tech debt this sprint?" |
| 结束会议 | "Alright, I think we have a solid plan. Let's get started!" |

## 13.4 技术评审会议（Tech Review）表达

技术评审会议是你展示方案设计能力的舞台。你需要在会议上陈述你的技术方案，回答来自各方的质疑，记录反馈并跟进。这不仅考验你的技术功底，更考验你的英语表达和临场应变能力。

### 陈述技术方案

陈述方案的核心逻辑是：**背景 → 问题 → 方案 → 取舍 → 计划**。

**开场与背景介绍：**

- "Thanks everyone for joining. Today I'd like to walk you through the proposed architecture for [feature/project]."
- "Let me start with some context. We're trying to solve [problem], and the current approach has limitations because [reasons]."
- "The motivation for this proposal comes from [incident/metric/requirement]. We need a better way to handle [scenario]."

**陈述方案：**

- "The high-level idea is to [approach]. Here's how it would work: [brief explanation]."
- "I'm proposing we use [technology/pattern] because [reason]. The alternative would be [alternative], but I ruled that out because [reason]."
- "Let me walk you through the architecture diagram. As you can see, the request flows from [A] to [B] to [C], and [explanation]."

**解释取舍（Trade-offs）：**

- "I considered three options: Option A is [description], Option B is [description], and Option C is [description]. I recommend Option [X] because [reason]."
- "The trade-off here is between [dimension A] and [dimension B]. I prioritized [A] because [reason], at the cost of [B]."
- "This approach gives us [benefit], but the downside is [cost/risk]. I think it's worth it because [justification]."
- "We're trading [short-term cost] for [long-term benefit]. In my opinion, it's the right call given [context]."

**陈述计划：**

- "The implementation plan is divided into three phases. Phase 1 is [milestone], Phase 2 is [milestone], and Phase 3 is [milestone]."
- "I estimate this will take about [time] with [number] engineers. The critical path is [task]."
- "For rollout, I suggest we start with a feature flag and gradually increase the traffic."

### 回答质疑与提问

技术评审中一定会有人提出质疑，这是正常流程，不是针对你个人。

**当你同意对方观点时：**

- "That's a fair point. I'll update the design to address that."
- "Good catch — I hadn't considered that scenario. Let me think about how to handle it."
- "You're right, that's a gap in the current proposal. I'll add a section on [topic] in the revised doc."
- "I agree. Let me incorporate that feedback."

**当你需要辩解或解释时（保持专业和开放）：**

- "I understand the concern. The reason I went with [approach] is that [explanation]. But I'm open to revisiting this if there's a better alternative."
- "That's a valid concern. I did look into [alternative], but it turned out to be [issue]. I can share my analysis if you're interested."
- "I see where you're coming from. In an ideal world, I'd agree with you. But given the [constraint], I think this is the most pragmatic approach."
- "Let me clarify — the intention here isn't to [misinterpretation], but rather to [actual intent]. Maybe I should make that clearer in the doc."

**当你不确定时（诚实是上策）：**

- "That's a great question. I don't have a definitive answer right now, but I'll investigate and follow up."
- "I need to think about that more carefully. Let me get back to you by [time]."
- "I'm not 100% sure. I'd like to do a quick prototype to validate before committing to this approach."
- "That's outside the scope of this proposal, but it's worth tracking. I'll create a follow-up ticket."

**当你不同意对方观点时（委婉但坚定）：**

- "I hear what you're saying, but I think [reason] makes this approach still the better choice. Happy to discuss further offline if you'd like."
- "I see your point, but I'd push back a little — [explanation]. The risk you mentioned is mitigated by [mitigation]."
- "I respectfully disagree on this one. My reasoning is [explanation]. But I'm open to being convinced otherwise if there's data I'm not aware of."

### 记录与跟进反馈

**会议中记录反馈：**

- "Let me note that down. I'll address it in the next revision."
- "Could you say more about that? I want to make sure I capture the full context."
- "I've logged that as an action item. I'll follow up in the [doc/ticket]."

**会议后跟进：**

```
Hi everyone,

Thanks for the great discussion in today's tech review. I've summarized the
key feedback and action items below:

1. [Feedback point 1] — Action: [what you'll do]
2. [Feedback point 2] — Action: [what you'll do]
3. [Feedback point 3] — Action: [what you'll do]

I'll update the design doc and circulate it by [date]. Please add any
additional comments directly in the doc.

Thanks,
[Your Name]
```

### Tech Review 高频句型

| 场景 | 英文表达 |
|------|---------|
| 引导看图 | "If you look at slide [N] / the diagram on the right..." |
| 强调重点 | "The key thing to notice here is..." |
| 预告内容 | "I'll get to that in a bit — it's on the next slide." |
| 检查理解 | "Does that make sense? Any questions so far?" |
| 控制时间 | "I want to be mindful of time, so let me skip to the recommendation." |
| 总结方案 | "To summarize, I'm proposing [approach] because [reason], with a timeline of [time]." |
| 邀请反馈 | "I'd love to get your thoughts. Any concerns or suggestions?" |

## 13.5 一对一会议（1-on-1）表达

1-on-1 是你和 manager 之间最私密的沟通渠道。它不是进度汇报会——进度汇报可以在 Slack 上完成。1-on-1 的真正价值在于：谈个人成长、给/收反馈、讨论困难、规划职业路径。很多程序员不擅长这些"软话题"，用英语谈更是难上加难。这一节给你准备好全套表达。

### 谈个人成长

**表达你想发展的方向：**

- "I'd like to grow in the direction of [area]. What opportunities do you see for me to develop that?"
- "I've been interested in [technology/skill] lately. Do you think there's a project where I could practice that?"
- "I feel like I've been doing a lot of [current work] and I'm ready to take on more [new type of work]. Is that something we can work toward?"
- "I want to eventually move toward [role/direction]. What gaps do you see between where I am and where I need to be?"

**请求具体的成长支持：**

- "Could I get a mentor or buddy for [area]? I think having someone to guide me would accelerate my learning."
- "Is there a training or conference I could attend? I think [event] would be really helpful for my growth."
- "I'd love to get more opportunities to do [activity] — like presenting at a tech review or leading a project. Is that realistic?"

### 给出和接收反馈

**给 manager 反馈（注意措辞）：**

- "I wanted to share some feedback about [topic]. I've noticed that [observation], and it impacts [effect]. Would it be possible to [suggestion]?"
- "One thing that would help me is if [change]. I find it easier to work when [condition]."
- "I appreciate [positive thing]. One area where I think we could improve is [area]. What do you think?"
- "I wanted to bring up something that's been on my mind. When [situation happens], I feel [feeling]. Can we talk about how to handle it differently?"

**接收反馈时的回应：**

- "Thank you for the feedback. I appreciate you being direct with me."
- "I hadn't realized I was doing that. I'll work on it."
- "That's helpful to hear. Could you give me a specific example so I understand better?"
- "I understand. What would good look like in that situation? I want to make sure I'm aligned with expectations."
- "Can we set up a check-in in [time] to see if I'm improving on this?"

### 讨论困难与挑战

**表达遇到的困难：**

- "I've been struggling with [issue] lately. It's affecting my [work/morale/efficiency]. I wanted to talk through it with you."
- "I'm feeling a bit overwhelmed with [situation]. I have [A], [B], and [C] on my plate, and I'm not sure I can do them all well."
- "To be honest, I'm finding [aspect of the job] quite challenging. I could use some guidance on how to approach it."
- "I ran into a difficult situation with [person/team] last week. I'd value your advice on how to handle it."

**请求帮助（不要不好意思）：**

- "I think I need more support with [area]. Would it be possible to [specific request]?"
- "I'm not sure I have the right context for [project]. Could you help me understand [background]?"
- "I'd benefit from more frequent check-ins during [project]. Would weekly syncs work for you?"

### 职业规划对话

**了解你在 manager 眼中的位置：**

- "Where do you see me in the next 6-12 months? What role do you think I'm best suited for?"
- "What do you think are my biggest strengths? And what's the one thing I should focus on improving?"
- "How am I tracking against the expectations for my level? Are there any gaps I should be aware of?"
- "What would it take for me to get to the next level? Can we map out a plan?"

**讨论晋升路径：**

- "I'd like to start working toward [promotion/level]. What does the process look like here?"
- "What artifacts or evidence do I need for the promotion packet? I want to start collecting examples."
- "Are there specific projects or impact areas you'd recommend I focus on to strengthen my case?"
- "Is there a timeline I should be aware of? When's the next promo cycle?"

**谈论长期目标：**

- "Long term, I see myself moving toward [direction]. Does that align with what the team needs?"
- "I'm not sure if I want to go the IC track or the management track. Can we talk through the pros and cons?"
- "My goal is to eventually [ambition]. What stepping stones do I need along the way?"

### 1-on-1 开场与结束模板

**开场（破冰 + 设定议题）：**

- "How was your weekend? ... So for today, I had a few things I wanted to cover: [topic 1], [topic 2], and [topic 3]. Does that work, or is there something you want to add?"
- "Thanks for making time. I've been thinking about [topic] and wanted to get your perspective. But first — how are things on your end?"

**结束（确认行动项）：**

- "To summarize, I'll follow up on [action 1] and [action 2], and you'll [action 3]. Sounds good?"
- "Great conversation today. I feel like I have a clearer picture of [topic]. I'll start working on [next step]."
- "Thanks for the feedback. I'll focus on [area] and we can check in on it next time."

## 13.6 跨团队协作沟通

在外企，你几乎不可能独自完成一个功能——前端需要和后端对齐 API，后端需要和平台团队协调基础设施，所有人都需要和安全团队确认合规性。跨团队沟通是"高级生存技能"，这一节教你如何高效地和其他团队打交道。

### 依赖协调

当你的工作依赖其他团队时，主动沟通、提前告知是关键。

**发起依赖请求：**

```
Hi [Team/Name],

I'm working on [project] on the [your team] side, and we have a dependency
on [team's work]. Specifically, we need [exact ask] by [date] to meet our
delivery target.

Here's the context:
- What we're building: [brief description]
- What we need from you: [specific request]
- Why we need it: [reason]
- Target date: [date] — this is driven by [deadline reason]

Could you let us know if this is feasible? Happy to jump on a call to
discuss details.

Thanks,
[Your Name]
```

**Slack 快速版：**

- "Hey [Name], my team is starting on [project] next sprint and we'll need [your team's thing]. Can you confirm the timeline on your end?"
- "Hi [Name], we're building a feature that depends on [API/service]. Is there a doc or person I should talk to for the integration?"

**跟进依赖进度：**

- "Just checking in — is [task] still on track for [date]? We're building our timeline around it."
- "Following up on the [dependency] — any updates? Let me know if there's anything blocking it on our side."
- "I saw the [component] is ready — that's great! We'll start integrating next week."

**当依赖方延期时：**

- "I understand [team] is facing some challenges. Given the delay, we might need to adjust our delivery date. Should I communicate that to stakeholders?"
- "Thanks for the update. Since [dependency] is pushed back, is there anything else we can work on in parallel to not lose time?"
- "Can we get an updated ETA? I need to communicate the impact to our PM."

### API 对齐

API 对齐是跨团队协作中最技术性的沟通，需要精确、无歧义。

**发起 API 对齐请求：**

- "We're designing the [feature] API and want to align with your team before finalizing. Here's the proposed contract: [link to doc]. Could you review and share feedback by [date]?"
- "I'm working on the integration with [your service]. I have a few questions about the API: 1. [question], 2. [question], 3. [question]."
- "Is there a Swagger/OpenAPI spec for [service]? I want to make sure I'm using the latest version."

**讨论 API 设计：**

- "For the [endpoint], are you returning [format A] or [format B]? The docs seem to show both."
- "We need an additional field in the response — [field name]. Would that be feasible to add?"
- "The current pagination approach isn't working well for our use case. Could we switch to cursor-based pagination?"
- "What's the rate limit for this endpoint? We might hit the ceiling during peak hours."
- "I noticed the error response doesn't include [field]. Would it be possible to add it? It would help with debugging."

**确认 API 变更：**

```
Hi [Name],

Thanks for the discussion on the API changes. To confirm what we agreed on:

1. [Change 1] — You'll implement, ETA [date]
2. [Change 2] — We'll implement on our side, ETA [date]
3. [Change 3] — Deferred to next quarter

I've updated the API spec doc: [link]. Please review and approve.

One more thing — do we need to coordinate the rollout? We want to make
sure the change is backward compatible.

Thanks,
[Your Name]
```

### 排期沟通

跨团队排期是最容易产生摩擦的环节。核心原则：**提前沟通、留 buffer、白纸黑字确认。**

**发起排期对话：**

- "We're planning to start [project] in [sprint/week]. Given the cross-team dependency on [team], we want to make sure the timelines align. When does your team have bandwidth?"
- "Our target launch date is [date]. Working backward, we need [dependency] by [date]. Does that work for your team?"

**当排期冲突时：**

- "I understand your team has other priorities. Is there a compromise — maybe a phased approach where we get [minimum viable version] first?"
- "If the full scope isn't feasible by [date], could we prioritize [subset]? That would unblock us."
- "Let me check with our PM on whether the deadline has flex. In the meantime, is there a rough ETA you can give me?"

**确认排期：**

- "Just to confirm — your team will deliver [item] by [date], and we'll start integration on [date]. Does that sound right?"
- "I'll put this in the project tracker so everyone has visibility. [link]"

### 跨团队沟通邮件模板

```
Subject: Cross-team coordination: [Project Name] — [Your Team] ↔ [Other Team]

Hi [Names],

Following up on our discussion, here's a summary of the cross-team
coordination plan for [Project]:

📋 Scope:
- [Your team] owns: [items]
- [Other team] owns: [items]

📅 Timeline:
- [Date]: [milestone 1]
- [Date]: [milestone 2]
- [Date]: [milestone 3 — target launch]

🔗 Key links:
- Project doc: [link]
- API spec: [link]
- Tracking ticket: [link]

👥 Points of contact:
- [Your team]: [Name]
- [Other team]: [Name]

Please review and flag anything that looks off. If we're aligned, I'll
consider this the agreed plan.

Thanks,
[Your Name]
```

### 跨团队协作黄金法则

| 原则 | 说明 |
|------|------|
| **Always write it down** | 口头沟通后一定要用邮件/Slack 确认，避免"我以为你说了" |
| **Be explicit about dates** | 用具体日期而非 "next week" 或 "soon" |
| **Provide context** | 不要只说"我需要 X"，要说"我需要 X，因为 Y，为了 Z" |
| **Respect their priorities** | 对方有自己的 roadmap，不要假设你的需求自动优先 |
| **Escalate early, not late** | 如果协调不顺利，及时升级，不要拖到 deadline 前一天 |

## 13.7 向上级汇报与向上管理表达

向上管理（Managing Up）是外企中高级别工程师的必备技能。它不是"讨好老板"，而是**让你的工作成果被看见、让风险被提前预警、让资源被合理分配**。用英语做这些事，需要一些特定的表达策略。

### 进度汇报

好的进度汇报 = **简洁的状态 + 关键进展 + 下一步计划 + 需要关注的事项**。

**Slack 周报模板：**

```
📋 Weekly Update — Week of [date]

✅ Completed:
- [Item 1] — [outcome/impact]
- [Item 2] — [outcome/impact]

📍 In Progress:
- [Item 1] — [status/ETA]
- [Item 2] — [status/ETA]

🔜 Next Week:
- [Item 1]
- [Item 2]

⚠️ Risks / Needs:
- [Risk or ask, if any]
```

**口头进度汇报（会议中）：**

- "We're on track with [project]. The backend is [percent]% done, and the frontend is [percent]% done. We expect to be ready for testing by [date]."
- "Quick status update: [feature] is feature-complete and in QA. We found a couple of minor issues but nothing blocking. On track to ship by [date]."
- "Since the last update, we've completed [milestone 1] and [milestone 2]. We're now starting on [next phase]. Overall, we're about [percent]% through the project."

**当进度落后时（诚实 + 补救方案）：**

- "I want to flag that we're slightly behind on [task]. The reason is [explanation]. Here's my plan to catch up: [plan]. I believe we can still hit the [date] target, but it'll be tight."
- "We've hit an unexpected issue with [area]. It's added about [time] to the timeline. I've already started on a mitigation plan — [plan]. I'll keep you posted on the progress."
- "To be transparent, [task] is taking longer than estimated. The complexity was underestimated. I'd recommend we either extend the deadline by [time] or descope [feature]. What do you prefer?"

### 风险预警

风险预警的核心是：**早说、说清楚、给方案**。不要等问题爆发了才上报。

**识别并报告风险：**

- "I want to proactively flag a risk: [description]. The potential impact is [impact]. I'm monitoring it closely and have a mitigation plan: [plan]."
- "There's a risk that [event] might happen. If it does, it would affect [scope/timeline]. The probability is [low/medium/high]. I recommend we [action]."
- "I'm seeing some early warning signs with [area]. Nothing's broken yet, but the trend is concerning. I think we should [action] before it becomes a bigger issue."

**升级问题（Escalation）：**

当问题超出你的处理范围，需要上级介入时：

- "I've been trying to resolve [issue] with [team], but we're not making progress. I think this needs to be escalated. Could you help facilitate a conversation?"
- "I want to escalate a cross-team conflict: [description]. I've tried [approaches], but we're at an impasse. Your intervention would help unblock things."
- "This issue is beyond what I can resolve at my level. The decision involves [stakeholders], and I'd recommend we bring in [person] to help arbitrate."

**升级时的邮件模板：**

```
Subject: [ESCALTION] [Issue description]

Hi [Manager],

I need to escalate an issue that I haven't been able to resolve through
normal channels.

📋 Issue: [Brief description]
 Impact: [What's affected]
 Timeline: [Urgency]

🔓 What I've tried:
1. [Action 1] — [result]
2. [Action 2] — [result]
3. [Action 3] — [result]

🙋 What I need:
- [Specific ask, e.g., "A conversation with [team lead] to reprioritize"]
- [Specific ask, e.g., "A decision on [topic] by [date]"]

I believe this requires your involvement because [reason]. Happy to provide
more context if needed.

Thanks,
[Your Name]
```

### 资源申请

当你需要更多人手、预算或工具支持时，你需要用"投资回报"的思路来请求，而不是单纯地"我不够了"。

**请求人力支持：**

- "Based on the current scope and timeline, I believe we need [number] additional engineers to meet the [date] target. Here's the breakdown: [workload analysis]."
- "We're at capacity with the current team. To take on [new work], we'd either need to add [resource] or descope [existing work]. Which would you prefer?"
- "I'd like to request a [role] for [project]. The ROI is [justification] — it would save [time] and reduce the risk of [risk]."

**请求工具/预算支持：**

- "I'd like to request a license for [tool]. It would [benefit]. The cost is [amount] per [period]. I've already evaluated [alternative], but [reason it doesn't work]."
- "We need to upgrade our [infrastructure/tool] to handle [load/scale]. The current setup is [issue]. The cost would be [amount], but the cost of not doing it is [risk/impact]."

**请求决策支持：**

当你需要 manager 做决策时，给出你的推荐而不是开放性问题：

- "I need a decision on [topic]. I've analyzed the options: Option A is [pros/cons], Option B is [pros/cons]. My recommendation is Option [X] because [reason]. Do you approve, or would you like to discuss further?"
- "There's a decision needed on [topic] by [date]. I've put together a one-pager with the options and trade-offs: [link]. My recommendation is [recommendation]. Could you review and let me know?"

### 向上管理的日常技巧

**让成果被看见（不是炫耀）：**

- "Just wrapped up [project] — it improved [metric] by [number]. Thought you'd want to know for the weekly report."
- "Quick win to share: we managed to [achievement] ahead of schedule. This unblocks [next thing]."
- "I wrote up a post-mortem for [incident] with lessons learned and action items: [link]. It might be useful for the broader org."

**主动提供信息（不等被问）：**

- "Heads up — there's a potential [issue/risk] I'm keeping an eye on. Nothing urgent yet, but I'll flag it if it escalates."
- "FYI, I noticed that [observation]. It might be worth bringing up in the [meeting/forum]."
- "I put together a summary of [topic] that you might find useful for [context]: [link]"

**管理期望值：**

- "I want to set expectations — [task] is likely to take [time] rather than [shorter time] because [reason]. I'd rather over-communicate now than miss the deadline later."
- "I'm confident we can deliver [core scope], but [stretch scope] is best-effort. Want me to prioritize accordingly?"

### 向上管理表达速查表

| 场景 | 英文表达 |
|------|---------|
| 同步好消息 | "Quick update — [good news]. This means [impact]." |
| 同步坏消息 | "I need to share a not-so-great update: [issue]. Here's what I'm doing about it: [plan]." |
| 请求决策 | "I need your call on [topic] by [date]. My recommendation is [recommendation]." |
| 请求资源 | "To deliver [goal], I need [resource]. The ROI is [justification]." |
| 确认对齐 | "Just to make sure we're aligned — the priority is [A] > [B] > [C]?" |
| 主动预警 | "Heads up on [risk] — I'm tracking it and will escalate if needed." |
| 汇报完成 | "[Project] is done. Here's a summary of what was delivered and the impact." |
| 拒绝不合理需求 | "I understand the urgency, but with current capacity, I can commit to [scope] by [date]. Anything beyond that would need [trade-off]." |

## 本章小结

外企日常办公英语，归根结底是在回答三个问题：**你在做什么？你需要什么？你发现了什么？** 无论是站会、Sprint Planning、技术评审、1-on-1、还是跨团队沟通，都是这三个问题的不同变体。

回顾本章的七个场景：

1. **入职第一周**——大胆问、主动认人、快速熟悉工具链。第一周是"问题豁免期"。
2. **Standup**——Yesterday / Today / Blockers 三段式，简洁有料，有阻碍及时说。
3. **Sprint Planning**——估算有理有据、提问不怕"蠢问题"、认领量力而行。
4. **Tech Review**——方案陈述讲清取舍、面对质疑保持开放、反馈记录跟进到底。
5. **1-on-1**——谈成长、收反馈、说困难、聊规划。这是你和 manager 的信任银行存款时间。
6. **跨团队协作**——依赖提前说、API 白纸黑字、排期留 buffer、一切沟通留痕。
7. **向上管理**——进度主动报、风险提前预警、资源用 ROI 论证、成果让上级看见。

最后送你一句话：**在外企，沉默不是金，沟通才是。** 你的技术能力再强，如果不能用英语清晰地表达出来，别人就看不见你的价值。从明天开始，挑两三个模板用起来，在实践中找到自己的节奏。Good luck! 🚀
