# 第 6 章：语音识别（ASR）与语音理解

> **系列文章：《语音与音乐的机器之魂》**
> ASR 是语音 AI 的另一核心方向——让机器"听懂"人类语言。本章从 GMM-HMM 到 Whisper 再到语音大模型，梳理 ASR 的完整技术脉络。

---

## 1. ASR 系统概述

```
音频 → 特征提取 → 声学模型 → 语言模型 → 文本输出
       (Mel/MFCC)    (AM)        (LM)
```

核心挑战：
- **声学变异**：口音、语速、噪声、混响
- **语言复杂**：同音词、新词、代码切换
- **实时性**：流式识别需要低延迟

## 2. 传统 ASR 架构

### 2.1 GMM-HMM 时代

经典三件套：声学模型（GMM）+ 时序模型（HMM）+ 语言模型（N-gram）。

```
音频 → MFCC特征 → GMM(帧级音素概率) → HMM(时序状态转移) → N-gram语言模型 → 文本
```

**GMM 的局限：**
- 假设特征服从高斯分布（实际不一定）
- 难以建模高维复杂分布
- 需要精细的状态绑定（决策树聚类）

**HMM 的局限：**
- 一阶马尔可夫假设太强
- 不能捕捉长程依赖

### 2.2 DNN-HMM 混合

2011 年，Microsoft 用 DNN 替换 GMM，词错率降低 30%：

```
音频 → 特征 → DNN(帧级音素后验) → HMM(解码) → 语言模型 → 文本
```

DNN 更强的建模能力 + HMM 的时序结构 = 当时最优组合。

## 3. 端到端 ASR

### 3.1 CTC（Connectionist Temporal Classification）

CTC 解决了 ASR 中"输入输出长度不对齐"的核心问题。

**关键思想：**
- 引入 blank 符号
- 允许多个路径映射到同一输出
- 损失函数对所有可能对齐求边际

```
输入: [h, h, e, _, l, l, _, l, o, _]  (_ = blank)
CTC去重: [h, e, l, l, o] → "hello"

输入: [h, _, e, _, l, _, o, _]
CTC去重: [h, e, l, o] → "helo"  (不同的对齐)
```

**代表模型：** DeepSpeech 2, wav2letter

**优点：** 不需要帧级标注，训练简单  
**缺点：** 假设帧间独立，不能直接建模语言

### 3.2 Attention-based（编码器-解码器）

```
音频 → 编码器 → 注意力 → 解码器 → 文本
```

编码器提取声学特征，解码器通过注意力机制"查看"编码器的所有输出，生成文本。

**Listen-Attend-Spell (LAS)：**
- Listener：金字塔 LSTM 编码器（逐步降采样）
- Attender：内容注意力
- Speller：RNN 解码器

**优点：** 端到端，质量高  
**缺点：** 不适合流式（需要完整句子）

### 3.3 RNN-T（RNN Transducer）

融合 CTC 和 Attention 的优势——**当前工业界流式 ASR 的主流**。

```
音频 → 编码器(Transcription Network) ──┐
                                        → Joint Network → 输出
上一个token → 预测网络(Prediction Network) ┘
```

RNN-T 的关键特性：
- **流式推理**：编码器因果处理，不等完整句子
- **在线输出**：边说边出文字
- **隐式语言模型**：预测网络学习了语言规律

## 4. 现代语音基础模型

### 4.1 wav2vec 2.0

自监督预训练 + 少量微调的新范式：

```
预训练：
  原始波形 → 卷积特征提取 → 掩码 → Transformer → 对比学习
                              ↓
                        离散量化目标（Gumbel-softmax）

微调：
  预训练Transformer → + CTC损失 → ASR
  （仅需10分钟-10小时标注数据）
```

**意义：** 证明自监督预训练在语音领域同样有效，减少对标注数据的依赖。

### 4.2 Whisper（OpenAI, 2022）

**ASR 领域的"Stable Diffusion"——开源即巅峰。**

特点：
- **68 万小时**多语言数据弱监督训练
- **多任务**：识别 + 翻译 + 语言检测 + 时间戳
- **零样本**泛化能力极强
- **鲁棒性**：对噪声/口音/代码切换表现好

架构：
```
音频 → Mel频谱 → 2层Conv → Transformer编码器 → Transformer解码器 → 文本/时间戳
```

简单但有效——关键在于**大规模多样化数据**。

Whisper 的限制：
- 非流式（需完整音频）
- 推理较慢（模型大）
- 中文识别不如专用模型

### 4.3 语音大模型（Speech LLM）

2024 年后的趋势——将语音理解纳入 LLM 框架：

```
语音输入 → 音频Tokenizer → [audio tokens] + [text tokens] → LLM → 输出
```

| 模型 | 能力 | 特点 |
|------|------|------|
| Qwen-Audio | 语音理解+问答 | 阿里开源 |
| GPT-4o | 实时语音对话 | 原生多模态 |
| LLaMA-Omni | 开源语音交互 | 低延迟 |
| SpeechX | 统一语音处理 | 多任务 |
| Spirit-LM | 语音-文本交织 | Meta |

**Speech LLM 的优势：**
- 统一理解与生成
- 利用 LLM 的推理能力
- 支持复杂指令（"请用开心的语气说"）
- 零样本泛化

## 5. ASR 评估

### 5.1 核心指标

**WER（Word Error Rate）：**

```
WER = (S + D + I) / N
S: 替换错误数
D: 删除错误数  
I: 插入错误数
N: 参考词数
```

| WER | 水平 | 场景 |
|-----|------|------|
| < 5% | 优秀 | 干净朗读 |
| 5-10% | 良好 | 会议记录 |
| 10-20% | 可用 | 电话/播客 |
| > 20% | 需改进 | 噪声环境 |

**CER（Character Error Rate）：** 中文等无空格语言使用

**RTF（Real-Time Factor）：**
```
RTF = 处理时间 / 音频时长
RTF < 1.0 → 可实时
```

### 5.2 鲁棒性测试

- **噪声测试**：不同 SNR 下的 WER
- **口音测试**：不同方言/口音
- **混响测试**：不同 RT60
- **代码切换**：中英混合
- **长音频**：10分钟+ 稳定性

## 6. 流式 ASR

### 6.1 chunk-based 处理

```
音频流 → [chunk 1 (300ms)] → [chunk 2] → [chunk 3] → ...
              ↓                ↓            ↓
          "你"             "你好"       "你好世界"
```

### 6.2 关键技术

- **流式 RNN-T**：天然支持在线推理
- **Chunk-Attention**：限制注意力窗口到最近 N 帧
- **因果卷积**：不使用未来信息
- **VAD**：检测语音段，静音段不处理
- **Endpointing**：判断用户说完了一句话

### 6.3 延迟优化

| 策略 | 效果 |
|------|------|
| 更小的 chunk | 更低延迟，但可能损失上下文 |
| 上下文携带 | 保留前 chunk 的隐状态 |
| 投机解码 | 先出部分结果，后修正 |
| 流式+离线双模型 | 快模型先出，精确模型后修正 |

## 7. 本章小结

ASR 技术经历了：

1. **GMM-HMM 时代**：精细但脆弱，需要大量专家知识
2. **DNN-HMM 过渡**：DNN 替换 GMM，保持 HMM 框架
3. **端到端时代**：CTC → Attention → RNN-T
4. **自监督时代**：wav2vec 2.0 证明预训练有效
5. **大模型时代**：Whisper 开源即巅峰，Speech LLM 统一理解与生成

核心趋势：**从分模块优化走向统一基础模型**，自监督预训练 + 少量微调成为新范式。
